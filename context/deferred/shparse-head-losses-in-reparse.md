# Разбор shell: команды в тексте, который bash разбирает повторно, теряются в редких формах (как и до волны)

**Что не так.** `shparse.parse` не видит команду, которую bash 5.3 исполняет, в четырёх формах фаззера `make bashdiff`
(`--target parser`, глубина 3). Все три — тексты, которые bash разбирает повторно при раскрытии: `$((…) …)` в `${…}`,
тело heredoc в подстановке в `$((…)`, группа `=~` с комментарием. Детектор их команд не проверяет (пропуск), если
рядом нет другой установки. HEAD (до волны правок shparse) теряет те же команды.

- Зерно 41, номер 12640: `'$(touch P7)'` в `$(( $( … [[ -z "$(… <<- E2 … E2)" ]]) '$(touch P7)' 1 ))` внутри
  `${u1-…}` в `` `…` ``. Потеряна P7: '…' в арифметике bash раскрывает как текст в "…", и `$(touch P7)` исполняется.
- Зерно 53, номер 5843: тело heredoc `<<-E7` в `$( cat - <<-E7 … )` внутри `${HOME+…}` в `$((…)`, которая стоит в
  `${u3:-…}`. Строка тела `\ttouch P6` и строка `\tE7E7`: bash исполняет `touch P6`, хотя для heredoc это тело.
  Вероятно, печать (print_comsub) или повторный разбор `$((…)` в `${…}` кончает тело иначе, чем чтение.
- Зерно 53, номер 7826: группа `=~` `($({ false; } || true #)$(|function f2() { v3=$'$(' \⏎; a4=('\'⏎touch P4)⏎};
  f2))`. Потеряна P4: при раскрытии группы `#` за пробелом — комментарий (extract_delimited_string), и конец `$(…)`
  с ним не тот, что у чтения. Тот же класс — `[[ a =~ ($(a #\⏎b=(⏎touch P4))) ]]`.
- Зерно 67, номер 6753 (найдено третьим кругом ревью): `((( $(cat <<E⏎touch P4⏎E) )) )` — bash исполняет P4
  (`(((` здесь — подоболочка с арифметикой внутри), разбор и HEAD команду тела не видят. Один уровень, без
  повторного разбора внутри `${…}`.

**Чем доказано.** Прогоном `tests/tools/bashdiff.py --target parser --seed N --depth 3 --count 20000` в песочнице
(2026-10-11): потери 1 (зерно 41), 2 (зерно 53) и 1 (зерно 67, третий круг ревью, зёрна 61–73); на остальных
зёрнах и на глубине 2 потерь нет. Разбор HEAD (`git show HEAD:plugin/planka/shparse.py`) теряет те же маркеры.

**Верное решение и цена.** Для каждой формы — найти по исходнику bash 5.3 (print_cmd.c, subst.c:
extract_delimited_string, xparse_dolparen; parse.y: make_here_document, parse_matched_pair), какой текст и с каким
знаком конца bash разбирает повторно, и повторить это в `_expanded_dparen`, `body_parts`, `group_word`. Для группы `=~`
нужен конец `$(…)` при раскрытии с комментарием — как `_xscan` для `$((`. Каждый класс — тест на форму, затем фаззер
на всех зёрнах × глубинах 2–3. Цена: несколько кругов правок повторного разбора с риском новых расхождений позиций
(`PositionsTest`).

**Почему отложено.** Решение автора 2026-10-11: хвост потерь, которые есть и в HEAD, записать долгом. Вес средний:
пропуск установки, но только в экзотической записи — вложенный повторно разбираемый текст или `((( $(…) )) )`; настоящие
команды корпусов так не пишут.
