# Сторож судьи и на Linux: смерть всей группы с хуком

**Что не так.** На Linux `common._start_judge` запускает судью с `preexec_fn`
`common._die_with_hook`: `PR_SET_PDEATHSIG` ставится только процессу `claude`, потомкам он не
наследуется. Хук, убитый Claude Code по таймауту или прерыванием, уносит с собой процесс `claude`, а
его потомки, если они есть, остаются работать; группу целиком убивает только `common._kill_group` —
по таймауту судьи, то есть пока хук жив. На других платформах вся группа умирает вместе с хуком через
сторож `common._WATCHDOG`.

**Чем доказано.** Чтением `common._die_with_hook` и `common._start_judge` (docstring: «его потомков
убивает только _kill_group по таймауту»); `PR_SET_PDEATHSIG` по prctl(2) действует на вызвавший
процесс и сбрасывается у потомков после `fork`. Порождает ли `claude -p --tools ""` потомков, не
установлено: живой `claude` не запускался, тесты идут на заглушке `tests/stub/claude`, которая делает
`exec`.

**Верное решение и цена.** Сторож `_WATCHDOG` и на Linux: он сверяет родителя с PID хука и убивает
всю группу. Цена — лишний процесс `python3` на каждый вызов судьи (запуск интерпретатора к времени
судьи) и проверка раз в `WATCHDOG_POLL`; `PR_SET_PDEATHSIG` можно оставить сторожу.

**Почему отложено.** Без потомков у `claude -p --tools ""` изъяна нет, а это не проверено; цена —
процесс на каждый вызов. Вес низкий.
