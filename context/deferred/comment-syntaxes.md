# Упрощённый разбор комментариев: регулярные выражения, slashy-строки, JSX, heredoc

**Что не так.** `comments._comments` разбирает файл по `comments._SYNTAX` без разбора выражений, поэтому
несколько конструкций читаются неверно:

- регулярное выражение JS с `//` или `/*` (`/\/\//`, `/a\/*/`) — начало комментария: строчного до конца
  строки или блочного до ближайшего `*/`;
- slashy-строка Groovy с `//` (`/http://x/`) — строчный комментарий;
- текст JSX и TSX с `//` (`<p>see http://x.y</p>`) — строчный комментарий;
- heredoc Ruby и Perl вплотную к слову (`x<<EOS`; в Perl — кроме `print<<EOT`, `print CSS<<EOF`,
  `print{$fh}<<EOF`) читается как сдвиг, а после слова и пробела со строчным идентификатором без `-`, `~`
  и кавычек (`puts <<eof`) — как добавление (`comments._heredoc_ok`): тело heredoc разбирается как код;
- блок-дескриптор Perl перед heredoc длиннее `comments._BLOCK_LOOKBACK` (256 знаков) не узнаётся
  (`comments._print_block`): heredoc читается как сдвиг, тело — как код.

Следствие — лишние строки «комментариев» у судьи документации; незакрытый мнимый блок `/*` в JS прячет
от судьи настоящие комментарии до ближайшего `*/`.

**Чем доказано.** Вызовом `comments._comments`: `"let r = /\\/\\//;\n"` (`js`) → `[(1, "//;")]`;
`"let r = /a\\/\\/b|c\\/*/;\n"` (`js`) → `[(1, "/*/;")]`; `"def u = /http://x/\n"` (`groovy`) →
`[(1, "//x/")]`; `"const a = <p>see http://x.y</p>;\n"` (`jsx`) → `[(1, "//x.y</p>;")]`;
`"s = x<<EOS\n# a\nEOS\n"` (`rb`) → `[(2, "# a")]`; `"puts <<eof\n# a\neof\n"` (`rb`) → `[(2, "# a")]`.

**Верное решение и цена.** Регулярные выражения JS и slashy-строки Groovy — отличать `/` деления от
начала литерала по предыдущему токену (разбор выражений с состоянием); JSX — разбор разметки внутри
выражений; heredoc Ruby `puts <<eof` неоднозначен и для самого языка без знания, что `puts` — метод.
Цена — разбор с состоянием в `comments._token` на каждый из языков, тесты на формы и риск нелинейного
времени на длинных строках (`_BLOCK_LOOKBACK` держит линейность разбора Perl).

**Почему отложено.** Ошибка здесь дешёвая: лишняя строка у судьи или пропуск комментария, судья
документации всё равно видит список изменённых файлов и сообщения агента. Вес низкий.
