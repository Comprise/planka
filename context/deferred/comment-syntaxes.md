# Разбор комментариев: свои слова Perl, области видимости Ruby, вложенность s{…}{…}e, входы-скрипты действий

**Что не так.** `comments._comments` разбирает файл без полного разбора языка (`context/architecture.md`,
«Комментарии изменённых файлов»); остаются:

- Perl: `/` и `<<` после голого слова, которого нет в `comments._PERL_TERM` и `comments._PERL_VALUE` и которое не
  объявлено в файле выше в том же пакете (`comments._PerlNames`) — имя из `use Module` (import), лексические `my sub`
  и `state sub`, функция, объявленная после места или в строке `eval`, `*name = sub…` — решает правило «аргумент
  вызова»: `/` вплотную к следующему знаку — регулярка (`comments._literal_opens`), `<<` — heredoc, если идентификатор
  с `-`, `~`, в кавычках или с заглавной буквы (`comments._heredoc_ok`); вплотную `foo<<EOS` — сдвиг. say, fc,
  evalbytes — так же (функции только с feature). Сигнатуры определяются по тексту всего файла (`_perl_signatures`):
  включение из import модуля не видно, слово `use … signatures` в комментарии считается включением. Пакет следует за
  скобками кода; несбалансированная скобка вне литералов его сдвигает. Разбор расходится с `perl -MO=Deparse` и в
  объявлениях файла: прототип на следующей строке (`sub foo` ⏎ `() {1}`) — имя читается термом, а не константой, и
  `foo /2` за ним — регулярка; ключ в кавычках `use constant { "B" => 2 }` не учитывается (`B /2` — регулярка); `}`
  блока `map { $_ } &foo /2` принимается за операнд, и `/` — регулярка (у perl `&foo / 2`);
- Ruby: `names` (`comments._ruby_locals`) — все имена файла, которым присвоено значение, без областей видимости
  (`def`, `class`, `module`): имя, введённое в другом методе, считается локальным — `/` и `<<` за ним деление и
  сдвиг, хотя это вызов метода; по той же причине регулярка-аргумент (`puts /a`) кончается со строкой, а у Ruby
  многострочна;
- вторые части `s{…}{…}e` сверх бюджета повторного разбора (`comments._CODE_BUDGET` · длина файла) и глубже
  `comments._MAX_CODE_DEPTH` (64) не разбираются как код; heredoc внутри замены не читается (perl читает его строки
  после всей конструкции);
- вход `with:` действия, кроме actions/github-script, разбирается как shell.

Следствие — лишняя строка «комментария» у судьи документации или пропущенный комментарий.

**Чем доказано.** Вызовом `comments._comments`: `"x = PI /2 # c\n"` (`pl`) → `[]` (PI не объявлен, импорт; perl: `'PI' /
2`, `# c` — комментарий); `"use POSIX;\n$a = floor /2; # c\n"` (`pl`) → `[]` (у perl `floor` — терм с прототипом из
import, верно; разобрать без исполнения import, отличает ли он `floor` от `PI`, нельзя); `"def f\n  a = 1\nend\ndef g\n
  a /b # c\nend\n"` (`rb`) → `[(5, "# c")]` (Prism: `a` в `g` — метод, `/b # c` — регулярка); девять вложенных `s{a}{` с
`f() # d` и переводом строки внутри, `}e` без другого текста и переводом строки в конце (`pl`, `"s{a}{" * k + "f() #
d\n" + "}e" * k + "\n"`) — суммарная длина вторых частей больше четырёх длин файла — → `[]`, восемь — комментарий
найден. Объявления и `map` (`pl`, 2026-10-11): `"sub foo\n() {1}\n$x = foo /2; # c\n"`, `"use constant { \"B\" => 2
};\n$x = B /2; # c\n"`, `"sub foo { 4 }\n@a = map { $_ } &foo /2; # c\n"` → `[]`, а `perl -MO=Deparse` (5.42.2)
печатает деление (`$x = 0.5`, `$x = 1.0`, `map({$_;} &foo / 2)`), и `# c` — комментарий; контроль — `sub foo () {1}`
на одной строке и `use constant { B => 2 }` → `[(2, "# c")]`. Версия HEAD (до правок волны) на трёх формах — тоже
`[]`.

**Верное решение и цена.**

- Perl: точного статического решения нет. Регулярка или деление, heredoc или сдвиг за словом зависят от того, объявлена
  ли к этому месту функция и с каким прототипом; функции ставит `use Module` — `import` исполняется при компиляции и
  может завести имя, вычисленное во время работы (`*{"main::$name"} = sub () {…}`). Разобрать без исполнения кода нельзя
  (доказательство Кеглера «Perl cannot be parsed»). Точные части сделаны — встроенные слова (`_PERL_TERM`,
  `_PERL_VALUE`) и имена, объявленные в файле выше в том же пакете (`_PerlNames`); сверено с `perl -MO=Deparse` (5.42).
  Остаётся то, что требует исполнения: импорт; `my sub` и `state sub` с областью блока (нужны лексические области, в
  скане экземпляров нет). Скан Perl-файлов машины — все `*.pm` и `*.pl` под `/usr` (`find /usr -type f`), 2246 файлов
  (2026-10-11): объявленные имена задеты в 2 файлах (Math/Complex.pm, Time/Local.pm), результат совпал с прежним
  правилом; `_comments` с правками того же дня (объявленные имена, сигнатуры, ведущее `::` в именах; `*`, `&`, `.` перед
  именем и встроенным словом; glob и вызов `&name` как операнд; прототипы анонимных `sub` и `$$)`) и `_comments` версии
  до них (HEAD 2a71196) дают на каждом из 2246 файлов один и тот же результат.
- Объявления и `map`: прототип за пробельными символами и переводом строки, ключ-строка в хеше `use constant` и `}`
  блока `map` как конец блока, а не операнд, разбираются статически — точное решение есть, цена — правка разбора
  объявлений (`comments._PerlNames`) и операнда за `}` с тестом на каждую форму и повторным сканом Perl машины.
- Ruby: точное решение — таблица локальных переменных по областям видимости, а её даёт только парсер. Лексер Ruby
  сам спрашивает парсер (`lvar_defined` в parse.y, так же Prism); `end` метода находится, только если отличать
  модификатор `if`/`while` от оператора, а это решает состояние лексера, то есть те же `/` и `<<`. Цена — свой парсер
  Ruby. Ошибка сейчас дешёвая: лишнее имя в `names` делает `/` делением, а регулярку-аргумент однострочной.
- `s{…}{…}e`: точного однопроходного решения нет. Perl снимает `\` перед разделителем во второй части до разбора её
  как кода (`s{a}{f("\}")}e`), а heredoc внутри замены читает строки после всей конструкции; кадр со стеком разбирал
  бы другой текст, чем perl. Закрытая часть разбирается повторно с общим бюджетом `_CODE_BUDGET` · `len(text)` на файл
  и пределом глубины `_MAX_CODE_DEPTH`, разбор линеен; `\` перед `{`/`}` второй части снимается, как в perl
  (`_perl_unescape`). Остаётся: часть сверх бюджета — строка; heredoc внутри замены не читается. Наибольшая глубина
  среди Perl машины — 3 (Encode/MIME/Header.pm): бюджет её покрывает.
- Входы-скрипты прочих действий: язык входа задаёт реализация действия (`action.yml` и код в его репозитории нужной
  версии), не файл workflow; без загрузки действия не решить. Shell верен для большинства: `#` — комментарий и в
  bash, Python, Ruby, PowerShell.

**Почему отложено.** Три формы объявлений и `map` есть и в HEAD и требуют нетипичной записи: прототип на отдельной
строке, ключ константы в кавычках, `&вызов /` сразу за блоком `map`. Ошибка здесь дешёвая: лишняя строка у судьи или
пропуск комментария, судья документации всё равно видит список изменённых файлов и сообщения агента. Вес низкий.
