# Упрощённый разбор комментариев: heredoc, slashy-строки, регулярка после `)`, литералы Ruby и Perl

**Что не так.** `comments._comments` разбирает файл по `comments._SYNTAX` без полного разбора выражений.
Регулярные выражения JS, slashy-строки Groovy и разметка JSX разбираются по предыдущему токену
(`comments._expr_start`, `context/architecture.md`, «Комментарии изменённых файлов»); остаются:

- heredoc Ruby и Perl вплотную к слову (`x<<EOS`; в Perl — кроме `print<<EOT`, `print CSS<<EOF`,
  `print{$fh}<<EOF`) читается как сдвиг, а после слова и пробела со строчным идентификатором без `-`, `~`
  и кавычек (`puts <<eof`) — как добавление (`comments._heredoc_ok`): тело heredoc разбирается как код;
- блок-дескриптор Perl перед heredoc длиннее `comments._BLOCK_LOOKBACK` (256 знаков) не узнаётся
  (`comments._print_block`): heredoc читается как сдвиг, тело — как код;
- многострочная slashy-строка Groovy кончается с первой строкой (`comments._token`: незакрытый в строке литерал
  кончается с ней) — её вторая и следующие строки читаются как код, `//` в них — комментарий;
- `/` после `)` — всегда деление (`comments._EXPR_AFTER` без `)`): регулярное выражение в `if (x) /re/.test(s)`
  читается как деление, `//` в нём — комментарий;
- `/` Perl после голого слова через пробел и вплотную к следующему знаку — регулярка-аргумент
  (`comments._literal_opens`): деление на константу (`PI /2`) прячет остаток строки; в Ruby то же для имени, не
  введённого как локальная переменная, а имя, введённое в другом методе, считается локальным (`comments._ruby_locals`
  не знает областей видимости);
- флаги многострочной регулярки не ищутся, если вторая часть `s{…}` стоит на следующей строке (`s{…}\n{…}x`):
  `#` в первой части остаётся комментарием и без флага `x`;
- вход `script` под `with:` разбирается как JavaScript, только если `uses: actions/github-script` того же шага стоит
  раньше `with:` (`comments._yaml_key`, словарь `uses`); `uses` после `with:` и входы-скрипты прочих действий на
  другом языке разбираются как shell;
- вторые части `s{…}{…}e` глубже `comments._MAX_CODE_DEPTH` (4) не разбираются как код.

Следствие — лишние строки «комментариев» у судьи документации или пропущенный комментарий.

**Чем доказано.** Вызовом `comments._comments`: `"s = x<<EOS\n# a\nEOS\n"` (`rb`) → `[(2, "# a")]`;
`"puts <<eof\n# a\neof\n"` (`rb`) → `[(2, "# a")]`; `"def u = /a\nb // c/\n"` (`groovy`) → `[(2, "// c/")]`;
`"if (x) /\\/\\//.test(y)\n"` (`js`) → `[(1, "//.test(y)")]`; `"x = PI /2 # c\n"` (`pl`) → `[]`;
`"def f\n  a = 1\nend\ndef g\n  a /b # c\nend\n"` (`rb`) → `[(5, "# c")]` (в Ruby `a` в `g` — метод, `/b # c` —
регулярка-аргумент); `"$s =~ s{\n a #b\n}\n{c};\n"` (`pl`) → `[(2, "#b")]`; шесть вложенных `s{a}{` с `f() # d` внутри
и `}e` (`pl`) → `[]`; `"- with:\n    script: |\n      // a\n  uses: actions/github-script@v7\n"` (`yml`) → `[]`
(скрипт прочитан как shell, комментарий JS `// a` пропущен).

**Верное решение и цена.** Многострочная slashy-строка — открытый литерал через строки с отличием от деления
по следующей строке; `)` перед `/` — знать, закрывает ли скобка условие `if`/`while`/`for` (стек скобок с
ключевым словом); `/` после слова в Perl — знать, константа или функция ли слово (прототипы и `use constant`), в
Ruby — области видимости локальных переменных (`def`, `class`, `module`); флаги `s{…}\n{…}` — поиск второй части на
следующих строках; `s{…}{…}e` любой вложенности — разбор без `_MAX_CODE_DEPTH`, каждая строка разбирается столько
раз, какова глубина; heredoc Ruby `puts <<eof` неоднозначен и для самого языка без знания, что `puts` — метод.
Цена — состояние разбора на каждый случай, тесты на формы и риск нелинейного времени на длинных строках
(`_BLOCK_LOOKBACK` держит линейность разбора Perl).

**Почему отложено.** Ошибка здесь дешёвая: лишняя строка у судьи или пропуск комментария, судья
документации всё равно видит список изменённых файлов и сообщения агента. Вес низкий.
