# Детектор зависимостей: значения через eval, nameref, присваивания по индексу и с преобразованием не прослеживаются

**Что не так.** `depcheck._values` собирает значения переменных и позиционных параметров только из прямых записей текста
команды: присваиваний, `set`, `read` с here-string или heredoc, `printf -v`, `for`. Мимо проходят значения, заданные
через `eval` (`eval set -- npm i lodash; "$@"`, `eval 'set -- x npm i lodash'; shift; "$@"`, `set -- x npm i lodash;
eval shift; "$@"`), ссылку `declare -n R=X` (`declare -n R=X; X="npm i lodash"; $R`) и массив, собранный присваиваниями
по индексу (`a[1]=npm; a[2]=i; a[3]=lodash; "${a[@]}"`), присваивание из ссылки с преобразованием (`X="npm i lodash";
Y=${X/q/z}; $Y`): детектор пропускает команду, bash исполняет `npm i lodash`.

**Чем доказано.** Исполнением: `dependency_add` и `dependency_doubt` на этих командах возвращают пусто; оракул `env -i
PATH= bash -c` с `command_not_found_handle` в пустом каталоге показывает вызов `npm i lodash`. `eval set`, `declare -n`
и массив по индексам проходят и в версии HEAD до этой правки.

**Верное решение и цена.** Разбор строки `eval` из литеральных слов как текста команды (тем же `_values`), значения
nameref — значения имени, на которое он указывает, массив по индексам — склейка значений элементов по порядку индексов,
присваивание из ссылки с преобразованием — значение «известно только при исполнении» (сомнение у имени, как
`_WHY_RUNTIME_NAME`). Цена — ещё три пути потока значений в `_values` и их бюджет в `_NAME_BUDGET`.

**Почему отложено.** Формы нетипичны для команд агента: в `tests/fixtures/bash-transcripts.jsonl` их нет. Обход
нетипичной записью — вес средний, как у значений из окружения
([depcheck-interpreter-strings-and-environment-values.md](depcheck-interpreter-strings-and-environment-values.md)).
