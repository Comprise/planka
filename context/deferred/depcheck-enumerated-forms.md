# Детектор зависимостей перечисляет формы записи установки

**Что не так.** `depcheck.dependency_add` и `depcheck.dependency_doubt` узнают установку пакета, только если форма
записи команды есть в коде поимённо: обёртки (`_WRAPPERS`), запускатели (`_RUNNERS`, `_NPX`, `_EXECS`), оболочки
(`_SHELLS`), вложенные команды (`_launched`), флаги со значением, пробный прогон (`_DRY_RUN_MANAGERS`). Форма, которой
нет
в списках, — пропуск. Каждая поимённая ветка закрывает одну форму, а неназванная форма той же установки проходит.

**Чем доказано.** Рост `depcheck.py` (`git show <коммит>:plugin/planka/depcheck.py | wc -l`): 326 строк в 0.2.0, 1265 в
0.4.0, 1495 в 0.6.0, 1678 в 0.6.4. После четырёх аудитов пятый (2026-10-08) нашёл 17 обходов на коде 0.6.4, все
воспроизведены вызовом `dependency_add`/`dependency_doubt` (оба пусты, контроль `npm install left-pad` — добавление):
heredoc с `$(npm install x)` в теле, `bash <<< '…'`, `echo '…' | bash`, `yarn add x --dry-run`, префикс длиннее 4096
символов, `sudo -uroot npm install x`, `A+=1 npm install x`, `M=npm; $M install x`, аргумент в обратных кавычках,
`npm exec pnpm add x`, `setsid npm install x`, `hatch -e env run pip install x`, `NPM install x`, `echo $[1<<2]` перед
командой, `fish <<'EOF'`, `pip install --editable=git+…`, `ssh host "npm install x"`. Исправление волны закрыло их
поимённо (в коде стало 2058 строк); новые формы того же вида (`direnv exec`, `parallel`, `taskset`, `pwsh
-EncodedCommand` — README, «Известные ограничения»; сокращения длинных флагов getopt — `su --comm 'npm i x'`)
остались.

**Верное решение и цена.** Сомнение по умолчанию там, где неизвестно, какую программу запустит команда: имя команды —
подстановка или переменная, текст отдаётся оболочке (конвейер, here-string, `<(…)`, `eval` вычисленной строки), в
аргументах неизвестной программы стоят слова «менеджер + глагол установки». Тогда новая форма попадает в сомнение
(отказ с обходом `PLANKA_DEP_OK=1`) без новой ветки, и списки обёрток и запускателей сводятся к тем, что нужны для
точного разбора пакета. Цена: переписать ветки `_parse`/`_find_doubt` под это правило и замерить ложные отказы на
корпусе
настоящих команд `tests/fixtures/bash-commands.jsonl` (1405 команд из транскриптов). Нынешний поимённый детектор на этом
корпусе ложно не останавливает ни одной команды (`CorpusTest`, ожидания сверены вручную); сколько ложных отказов даст
правило сомнения — не замерено.

**Почему отложено.** Поимённые исправления волны закрывают все известные обходы, а ложных остановок на корпусе нет;
сравнение двух подходов на корпусе не сделано, без него переделка — решение без данных. Вес средний: обход требует
нетипичной записи команды.
