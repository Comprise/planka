# Детектор зависимостей перечисляет формы записи установки

**Что не так.** `depcheck.dependency_add` и `depcheck.dependency_doubt` узнают установку пакета по формам, которые
названы в коде: обёртки (`_WRAPPERS`), запускатели (`_RUNNERS`, `_NPX`, `_EXECS`), оболочки (`_SHELLS`), вложенные
команды (`_launched`), флаги со значением, пробный прогон (`_DRY_RUN_MANAGERS`). Неназванные формы частично ловят два
сомнения общего вида (`context/architecture.md`, «Детектор зависимостей»): вычисляемая строка оболочки
(`_computed_script`, `_WHY_COMPUTED`) и неизвестная программа со словами «менеджер + глагол установки или флаг», если
слова с менеджера — добавление или сомнение (`_launches_install`, `_WHY_LAUNCHER`). Мимо обоих проходят:

- неизвестная программа, которая получает команду одной строкой или из stdin: `docker exec c sh -c 'npm i x'`,
  `parallel ::: 'npm i x'`, `echo npm i x | parallel`;
- имя команды — переменная без глагола установки следом: `X="npm install x"; $X`;
- имя команды — вывод подстановки, глагол которой — в теле heredoc (символы `$(`, `${ `, `<<` в `_parse` и
  `_quoted_substitutions`: тело heredoc — данные, `_WHY_NAME` смотрит только слова подстановки): `x=${ $(cat <<E` ⏎
  `npm i x` ⏎ `E` ⏎ `); }`, `x=$( $(cat <<E` ⏎ `npm i x` ⏎ `E` ⏎ `) )`. bash 5.3 исполняет вывод `cat` командой:
  прогон с `touch PWNED` вместо установки создал файл; HEAD и 0.6.7 — пропуск;
- glob в имени (`/usr/bin/np? install x`), alias (`alias n=npm; n install x`), функция с пересылкой аргументов
  (`f(){ npm "$@"; }; f install x`);
- сокращения длинных флагов обёрток, которые принимает getopt_long: `su --comm 'npm i x'`, `runuser --us app -- npm i
  x`;
- `pwsh -EncodedCommand`, `pnpm dlx -c '…'`, `npm exec -c '…'`, `sudo -s '…'`, `fish -C '…'`/`--init-command '…'`,
  `su -s "$VAR" app` с командами из stdin;
- команды, которые запускает git, кроме названных в `_git_runs`: `git -c core.pager='…'`, `git -c core.sshCommand='…'`,
  `git filter-branch --tree-filter '…'` и другие `--*-filter`, `git difftool -x '…'`, псевдонимы из конфига git.

**Чем доказано.** Вызовом `dependency_add` и `dependency_doubt` на каждой форме списка: оба пусты (контроль
`npm install left-pad` — добавление). Корпус `tests/fixtures/bash-commands.jsonl` — 1405 настоящих команд из
транскриптов: разбор даёт 5 добавлений, 1 сомнение и 1399 пропусков, как в ожиданиях (`CorpusTest`); сомнение —
единственный ложный отказ, вычисляемый `sh -c "$(jq -r '.statusLine.command' …)"` (образец с ключом `"//"`).
Широкий вариант сомнения (любая вычисляемая строка и любая неизвестная программа с менеджером в аргументах) при
правке дал на том же корпусе 13 ложных отказов из 1400 и отвергнут; в коде он не сохранён — замер не воспроизводится.

**Верное решение и цена.** Сомнение по умолчанию там, где неизвестно, какую программу запустит команда, без поимённых
веток: строка или stdin, отданные неизвестной программе, имя команды из переменной, glob, alias и функция. Цена —
ложные отказы на обычных командах: `docker exec c sh -c '…'`, `parallel`, функции оболочки встречаются в работе
агента без установки пакетов, а широкий вариант уже дал 13 ложных отказов на корпусе. Точнее — разбор аргументов
каждой такой программы поимённо (как `_WATCH_EXEC` у `watch`), это и есть нынешний путь. Для имени команды из вывода
подстановки с heredoc верное решение — разбор `depcheck.py` по грамматике bash 5.3 (одно дерево слов, подстановок и
heredoc): сомнение `_WHY_NAME` смотрит и тело heredoc подстановки в позиции имени; цена — переписывание разборщика,
план готовится отдельно.

**Почему отложено.** Оставшиеся формы требуют нетипичной записи команды, ложных пропусков на корпусе настоящих команд
нет, а общее сомнение по ним даёт ложные отказы на обычной работе; форма с heredoc в подстановке-имени ждёт
переписывания разбора по грамматике — поимённая ветка в нынешнем лексере была бы ещё одной частной формой. Вес средний: обход проверки нетипичной записью.
