# Пропуски детектора зависимостей без предупреждения

**Что не так.** `depcheck.dependency_add` при сомнении в разборе возвращает `None`, и `judge_tool.judge_bash`
молча переходит к снимку манифестов. Формы — из `README.md`, «Известные ограничения», детектор зависимостей:
флаг со значением вне известных наборов перед подкомандой (значение принято за подкоманду), `--dry-run` значением
чужого флага, `npm --dry-run false install x`, пакеты из stdin `xargs`, вложенность глубже 4 уровней, пакет дальше
4096 символов сегмента. По правилу о краях эвристик (`CLAUDE.md`, «Правила проекта») каждая из этих форм — то же
добавление пакета другой записью: пропуск открывает обход проверки, и их ветка — оставленный отказ с обходом
маркером, а не пропуск с предупреждением.

**Чем доказано.** `grep -c warn plugin/planka/depcheck.py` — `0`; вызовы 2026-10-08: `dependency_add('npm --weird
val i -g x')`, `dependency_add('pip install --target --dry-run x')`, `dependency_add('npm --dry-run false install
x')`, `dependency_add('echo x | xargs npm install')` — все `None`, при том что `dependency_add('npm i -g foo')` —
отказ. Добавление в манифест после такой команды ловит сравнение манифестов
(`judge_tool.check_command_manifests`); установка без записи в манифест (`npm --weird val i -g x`, системный
пакет) проходит молча.

**Верное решение и цена.** Детектор отдаёт сегмент с распознанными менеджером и подкомандой установки, где
пакет или подкоманда под сомнением, как добавление: отказ с причиной о сомнении и маркером `PLANKA_DEP_OK=1`;
тест на каждую форму. Цена — ложный отказ там, где неизвестный флаг на деле без значения (строка в README с
обходом маркером), и прогон на настоящих командах из транскриптов, чтобы отказ не задел обычные команды.

**Почему отложено.** Правило о краях эвристик записано 2026-10-08 после этих форм; правка детектора —
отдельная задача с прогоном на настоящих командах.
