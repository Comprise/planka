# Имя пакета манифеста HEAD прикрывает имя во всём реестре у cargo, composer, go

**Что не так.** `manifest_watch._tree_names` и `project_names` добавляют имя пакета манифеста версии HEAD или ref
(`manifests.own_name`: `package.name` Cargo.toml, `name` composer.json, `module` go.mod) в имена проекта своего реестра,
и любая зависимость с этим именем в другом манифесте реестра — не новое имя. Для npm и PyPI это закрыто
(`_WORKSPACE_ROOTS`: имя пакета манифеста HEAD зависимость не прикрывает, местная она только по связи workspace). У
cargo, composer и go остался тот же класс обхода: закоммитить манифест с чужим именем, затем добавить зависимость на
него — менеджер поставит пакет из реестра, а хук его не отметит.

**Чем доказано.** Чтением: ветка `if kind not in _LEGACY and manifests.registry(kind) not in _WORKSPACE_ROOTS` в
`_tree_names` добавляет `own_name` для всех видов, кроме npm и PyPI. Проверено исполнением: в git-репозитории с
закоммиченным `tools/x/Cargo.toml` (`name = "serde"`) вызов `manifest_watch.check_edit` на правку корневого `Cargo.toml`
с `serde = "1"` вернул `[]` (контроль: `rand` — `['rand']`).

**Верное решение и цена.** Засчитывать имя только там, где менеджер свяжет его с каталогом: Cargo `[workspace]` и
зависимость с `path`, `path`-repositories composer, `replace` в `go.mod` и `go.work`. Цена — разбор workspace каждого
менеджера и ложные отказы там, где разбор не угадал связь.

**Почему отложено.** Нет проверенного по исходникам или документации менеджеров описания, когда они берут пакет из
каталога; непроверенное правило дало бы либо ложные отказы, либо новый обход. Вес средний: обход проверки в нетипичной
записи (манифест с чужим именем, закоммиченный до зависимости).
