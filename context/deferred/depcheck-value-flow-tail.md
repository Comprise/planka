# Детектор зависимостей: хвост потоков значений и кода интерпретаторов — редкие записи установки проходят без отказа

**Что не так.** `depcheck` собирает значения переменных и командные строки в коде интерпретатора не во всех формах
(устройство — `context/architecture.md`, «Детектор зависимостей»). Мимо `dependency_add` и `dependency_doubt` проходят:

- `a=(npm i x); set -- "${a[@]}"; "$@"` — слова `set` не раскрываются значениями массива: позиционные параметры —
  текст слова `"${a[@]}"`, а не `npm i x`;
- `IFS=: ; X='npm:i:x'; $X` — заданный в тексте `IFS` не делит значение ссылки без кавычек при раскрытии (`_var_values`,
  `_composed`); `IFS` учитывается только у `read`;
- `printf -v 'a[0]' npm; a[1]=i; a[2]=x; "${a[@]}"` — `printf -v` в элемент массива не даёт события элемента: цель
  `printf -v` не разбирается через `_indexed`;
- `for w in npm i x; do c+=($w); done; "${c[@]}"` — переменная цикла в `+=(…)` берётся своим текстом, а не значениями
  цикла;
- `python3 -c "…; subprocess.run(['npm', 'i', pkg])"` — список с нелитералом не склеивается: `_CODE_LIST` берёт только
  строковые литералы подряд;
- `node -e "…spawnSync('npm', ['i', 'x'])"`, `execFile('npm', [...])` — программа и список аргументов разделены, и ни
  отрезок `_code_lines`, ни список `_CODE_LIST` не несут менеджера вместе с глаголом;
- `yarn node -e "…execSync('npm i x')"` — `yarn node` не запускатель в `_launch_target`, код за ним не читается;
- `mawk -f /dev/stdin <<E` с `system("npm i x")` в теле — программа awk из stdin (`-f`) не видна как код;
- `os.system("npm " + "i x")` — литералы, склеенные через `+`, не склеиваются в один кандидат;
- `os.system("npm\x20i x")`, `"np\x6d i x"` — экранирования в литералах кода не раскрываются;
- `a=([${#b[@]}]=npm i x); "${a[@]}"` — ключ элемента с `]` внутри скобок: `_ITEM_INDEX` ищет первую `]` без
  вложенности, и массив не получает значений;
- `a[${x:-]}]=npm; a[1]=i; a[2]=x; "${a[@]}"` — `]` внутри раскрытия в индексе: `_indexed` считает только пары `[`/`]`
  и обрывает индекс на `]` раскрытия, слово не присваивание элементу; так же `_indexed` разбирает цель `unset "a[…]"`;
- `P=npm; ./run.sh $P i lodash` — неизвестная программа со словами из переменной и литералов: `_launches_install`
  смотрит сырые слова, а не их значения;
- `awk -f p.awk npm i x` — слова за файлом программы awk (её `ARGV`) не склеиваются: `_script_args` у awk пуст, а
  `_code_doubt` смотрит каждое слово отдельно.

Установка пакета так же, как явная, — обход проверки нетипичной записью.

**Чем доказано.** Исполнением (2026-10-11): `dependency_add` и `dependency_doubt` на каждой форме выше возвращают пусто;
контроль — `a=(npm i x); "${a[@]}"`, `set -- npm i x; "$@"` и `a=([0]=npm i x); "${a[@]}"` — сомнение `_WHY_RENAMED`,
`python3 -c "subprocess.run(['npm', 'i', 'x'])"` — `_WHY_INTERPRETER`, `a[0]=npm; a[1]=i; a[2]=x; "${a[@]}"` —
`_WHY_RENAMED`, `./run.sh npm i lodash` — `_WHY_LAUNCHER`. Формы проходят и в HEAD (до волны правок детектора).

**Верное решение и цена.** По форме:

- `set`: раскрывать слова `set` значениями ссылок через `_var_values` с учётом кавычек;
- `IFS`: делить значения ссылок без кавычек по известным значениям `IFS` в `_var_values` и `_composed`; `IFS`, заданный
  при исполнении, — `_RUNTIME_VALUE`;
- `printf -v` в элемент: цель через `_indexed` и событие элемента, как у присваивания `a[0]=…`;
- `+=(…)` в цикле: элемент из одной ссылки на переменную цикла — значения переменной цикла;
- `_CODE_LIST`: идентификатор или выражение в списке — слово с раскрытием `_PLACEHOLDER`;
- программа и список: склеивать строковый литерал со следующим литеральным списком;
- `yarn node`, `pnpm node`, `npm exec node` — в `_launch_target`;
- awk с `-f` из stdin (`/dev/stdin`, `-`) — интерпретатор со stdin;
- склейка литералов через `+`, `.`, `..` в `_code_lines`;
- раскрытие `\xHH`, `\NNN`, `\uHHHH` в литералах по языку интерпретатора;
- ключ элемента — тот же поиск парной `]`, что в `_indexed`;
- индекс с `]` в раскрытии: имя и индекс присваивания и цели `unset` брать из узла `shparse` (`_assignment`,
  `_skip_subscript` уже находят конец индекса, как bash), а не счётом скобок в `_indexed`; неразобранный индекс —
  `_RUNTIME_VALUE`;
- неизвестная программа: проверять в `_launches_install` и значения слов (`_word_values`) в пределах `_NAME_BUDGET`;
- `awk -f`: в `_script_args` брать у awk операнды за текстом программы или файлом `-f`, кроме `var=value`.

Каждая форма — своя правка разбора с тестом; правки кода интерпретаторов (склейка, экранирования, списки с
нелитералами) расширяют кандидатов `_code_lines` и дают новые ложные отказы на литералах, которые код не исполняет.

**Почему отложено.** Решение автора 2026-10-11: хвост форм, которые проходят и в HEAD, записать долгом. Вес средний:
обход проверки, но только нетипичной записью, которую агент выбирает намеренно; обычная установка и известные формы
переноса значений ловятся. Перечень пропусков — `README.md`, «Известные ограничения».
