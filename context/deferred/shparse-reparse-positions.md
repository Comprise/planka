# Разбор shell: позиции частей в повторных разборах одним сдвигом

**Что не так.** Слово, раскрытое заново по напечатанному тексту (`shparse._reexpand_word`), переводит позиции частей в
исходный текст по кускам (`_render(where=…)`, `_printed_pieces`). Остальные повторные разборы — `_arith_or_comsub`,
текст `'…'` арифметики (`arith_quote`), `<(…)` внутри `${…}` — переводят позиции одним сдвигом от начала куска с
пределом его конца: позиции в границах текста, но внутри подстановки могут указывать не на свой символ, если печатный
текст длиннее или короче исходного.

**Чем доказано.** Чтением кода `plugin/planka/shparse.py` (вызовы `_R(text, [(0, …)], …)` в этих ветках) и отчётом
правки позиций; инвариант `0 ≤ start ≤ end ≤ len(text)` проверяют `PositionsTest` на корпусах и формах фаззера —
он соблюдён, точность позиций внутри подстановки не проверяется.

**Верное решение и цена.** Тот же кусочный перевод (`_render(where=…)`, `_printed_pieces`) для каждого повторного
разбора по печатному тексту и тест: текст каждого узла по его позициям совпадает с его текстом в дереве на корпусах и
формах фаззера. Цена — правка трёх веток shparse и тест.

**Почему отложено.** Найдено при исправлении находок ревью: детектор и потребители берут из этих позиций только
границы сегментов в пределах текста, неверного вердикта не найдено; вес низкий.
