# Ярус модели судьи

**Что не так.** Настройка `judge_model` (`plugin/.claude-plugin/plugin.json`) по умолчанию — `session`: судья зовёт
модель сессии (`model_watch.py` запоминает её). В сессии на фронтире каждая проверка судьи — `judge_tool.py`,
`judge_stop.py`, `guard_memory.py` — идёт на фронтире, хотя часть вопросов проще; какую модель ставить, неизвестно:
замера качества судьи по моделям нет.

**Чем доказано.** Чтением кода и `CLAUDE.md`, раздел `plugin/planka/`: «`model_watch.py` (`SessionStart`,
`PostModelSwitch` — модель сессии для судьи)». Затраты судьи по ярусам не замерялись.

**Верное решение и цена.** Каскад: детерминированные проверки → судья стандартного яруса → фронтир только при
сомнении или отказе; ярус меняется только после замера на размеченном наборе случаев (нарушение есть / нет) — судья
нижнего яруса ловит нарушения не хуже. Цена: размеченный набор, прогон настоящих моделей; по итогу замера — значение
`judge_model` по умолчанию и, если нужен, каскад в коде судьи.

**Почему отложено.** Решение автора 2026-10-10: из правил выбора модели взяты пункты о делегировании, условиях
дешёвого яруса и ярусе проверяющего; ярус судьи — отдельной задачей с замером. Вес низкий: затраты, а не корректность.
