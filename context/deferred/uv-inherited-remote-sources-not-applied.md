# Удалённые источники корня uv, наследуемые членом, не применяются к его зависимостям

**Что не так.** `manifest_watch._uv_inherited` отдаёт члену uv workspace только имена с местным источником корня
(`manifests.uv_sources`, `_uv_local`: `workspace = true` или `path`). Член, наследующий `x = { git = … }` или `x = {
index = … }` из `[tool.uv.sources]` корня, разбирается как зависимость от простого имени `x`, а не `x @ git+…` или
`index <url>`, как было бы при тех же источниках в самом члене (`manifests.names`).

**Чем доказано.** Чтением `_uv_inherited` и `manifests.uv_sources`: словарь хранит один признак «местный» на имя,
источник и его адрес не сохраняются. Наследованный удалённый источник корня — ещё и пропуск смены источника: если имя
`x` уже объявлено в другом манифесте проекта или версии HEAD, член с простым `x` даёт имя, известное проекту, и хук
молчит, хотя uv поставит `x` из git или чужого индекса. Проверено исполнением: корень uv workspace с `requests = { git =
… }` в `[tool.uv.sources]` и `requests` в `dependencies`, соседний член с простым `requests` (закоммичено);
`manifest_watch.check_edit` на правку члена, добавляющую `requests`, вернул `[]` (контроль: `flask` — `['flask']`). Без
соседа с простым `requests` результат `['requests']`: имя корня с источником — `requests @ git+…`, и простое имя члена
от него отличается.

**Верное решение и цена.** Хранить в `uv_sources` разобранные источники имени и подставлять их члену, не задавшему свой
(как делает uv), — разбор `manifests.names` вызывается на объединённой таблице. Цена — `names` получает таблицу корня
параметром, а `check_edit` и `compare` читают корень для каждого члена.

**Почему отложено.** Редкая конфигурация: удалённый общий источник в `[tool.uv.sources]` корня uv workspace и член с
этим именем без своего источника. Но это обход: если имя уже известно проекту (другой манифест, HEAD), смена источника
на git или чужой индекс проходит молча. Вес средний.
