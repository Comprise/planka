# Детектор зависимостей: значения из окружения, строка со значением из `read` и аргументы кода не подряд не проверяются

**Что не так.** `depcheck._renamed` и `_values` видят значения переменных и alias только из текста команды;
`_code_doubt` ищет установку в коде интерпретатора по кандидатам `_code_lines` — отрезкам между символами
`_CODE_SPLIT`, склейкам литерала со значением и спискам строковых литералов подряд через запятую (`_CODE_LIST`), — а
не разбором его языка. Мимо проходят:

- значение переменной или alias из окружения (`$PM` и `$PM x` без присваивания в тексте, где `PM='npm i'` задан в
  окружении; `$PM install x` — уже сомнение `_WHY_NAME`), в том числе имя программы:
  `C='npm i x'; $D exec c sh -c "$C"` при `D` из окружения — строку `$C` со значением из текста `_string_doubt` не
  проверяет (у имени-ссылки значения слов подставляет `_renamed`, а значения `D` в тексте нет);
- строка программы со значением, известным только при исполнении: `read X < f; docker exec c sh -c "$X"` (значение
  `read` из файла, `mapfile`, индекс не литералом — `_RUNTIME_VALUE` — у имени команды даёт сомнение
  `_WHY_RUNTIME_NAME`, а у строки программы `_WHY_STRING` его не даёт: `_word_values` такое значение пропускает);
- аргументы в коде, где литералы не стоят подряд: `deno eval "new Deno.Command('npm', {args: ['i', 'x']})"` — между
  `'npm'` и списком `['i', 'x']` стоит `{args:`, и ни отрезок, ни список `_CODE_LIST` не несёт слова менеджера вместе
  с глаголом установки.

Установка пакета так же, как явная, — обход проверки.

**Чем доказано.** Исполнением (2026-10-11): `dependency_add` и `dependency_doubt` на `$PM x`, на `C='npm i x'; $D exec
c sh -c "$C"`, на `read X < f; docker exec c sh -c "$X"` и `read X < f; docker exec c sh -c "echo $X"` и на `deno eval
"new Deno.Command('npm', {args: ['i', 'x']}).outputSync()"` возвращают пусто; контроль — `$PM install x` — сомнение
`_WHY_NAME`, `read X < f; ssh host "echo $X"` — `_WHY_COMPUTED`, `D=docker; C='npm i x'; $D exec c sh -c "$C"` —
`_WHY_STRING`, `python3 -c "subprocess.run(['npm', 'i', 'x'])"` — `_WHY_INTERPRETER`.

**Верное решение и цена.** Окружение и файлы в тексте команды не видны вовсе: их проверка потребовала бы читать
окружение хука и файлы, а окружение Bash к моменту команды может отличаться от окружения хука. Аргументы кода не подряд
— разбор вызовов по языку интерпретатора (Python, JS, Ruby, Perl, PHP…), а не по отрезкам: свой разборщик на язык.
Строка со значением `read` — сомнение у любой программы, чья строка содержит ссылку со значением `_RUNTIME_VALUE`; цена
— ложные отказы на формах, которые сейчас проходят: `read X < f; docker exec c sh -c "echo $X"` (`read X < f; ssh host
"echo $X"` — уже сомнение `_WHY_COMPUTED`).

**Почему отложено.** Агент, обходящий проверку значением из окружения, вызовом с аргументами вразбивку или `read`,
делает это намеренно; сомнение на каждой строке с `read`-значением дало бы ложные отказы на обычной работе. Вес
средний: обход проверки нетипичной записью. Перечень пропусков — `README.md`, «Известные ограничения».
