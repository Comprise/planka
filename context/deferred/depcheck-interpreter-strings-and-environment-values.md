# Детектор зависимостей: строки интерпретаторов и значения из окружения не проверяются

**Что не так.** `depcheck._string_doubt` и `_program_inputs` не смотрят на строки и stdin интерпретаторов
(`_CODE_PROGRAMS`: `node`, `perl`, `ruby`, `php`, `lua`, `r`, `julia`, `osascript`; `pkgmanagers._PYTHON`), `_renamed` —
на значения переменных и alias не из текста команды. Мимо проходят `python3 -c "os.system('npm i x')"`, `node -e`,
`perl -e`, сомнение внутри строки или значение из переменной (`docker exec c sh -c "$CMD"`), значение переменной или
alias из окружения, значение `read` из файла или конвейера, `mapfile`/`readarray`, скрипт оболочки со строкой-аргументом
(`bash run.sh 'npm i x'`). Установка пакета так же, как явная, — обход проверки.

**Чем доказано.** Исполнением: `dependency_add` и `dependency_doubt` на перечисленных командах возвращают пусто
(контроль `docker exec c sh -c 'npm i x'` — сомнение `_WHY_STRING`). Замером при правке: без исключения интерпретаторов
`_text_program` дал 86 ложных отказов на командах `bash-transcripts.jsonl`; вариант в коде не сохранён, замер не
воспроизводится.

**Верное решение и цена.** Сомнение на строке установки в коде интерпретатора. Цена — ложные отказы на литералах
(`python3 -c "print('npm i x')"`, `node -e` с текстом справки): 86 на настоящих транскриптах. Значения из окружения и
скрипты из файлов в тексте команды не видны вовсе — их проверка потребовала бы читать окружение и файлы.

**Почему отложено.** Цена в ложных отказах на обычной работе выше найденного обхода: агент, обходящий проверку строкой
интерпретатора, делает это намеренно. Вес средний: обход проверки нетипичной записью. Перечень пропусков — `README.md`,
«Известные ограничения».
