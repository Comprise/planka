# planka — модули правил и принудительная подгрузка через судей

Дата: 2026-10-07. Заменяет раздел 3 спеки `2026-09-30-planka-design.md` (текст правил) и
дополняет разделы 6–7 (судьи). Остальное в той спеке действует.

## 1. Задача

Обогатить плагин правилами из `awesome-agents-md` так, чтобы правила, уже заложенные в
`philosophy.md`, остались основой, а добавленные им не противоречили. Источник — конкурирующий
плагин: его ядро несёт лестницу «кратчайший дифф», лимит ответа в 35 слов, «группировать план по
поведению, а не по файлам» и строку о приоритете режимов минимализма. Всё это спорит с разделом
«Решения» и отброшено; берётся то, что дополняет.

## 2. Решения автора

Приняты 2026-10-07, каждое с вариантами по «Решениям» 4:

- **Структура — ядро плюс модули с принудительной подгрузкой через судей.** Единый файл отвергнут:
  ~160 инструкций на каждом ходе за порогом надёжного следования, просядет и главное правило.
  Рекомендательные модули без судьи отвергнуты как «срабатывает не всегда».
- **Объём модулей — все восемь:** verification, debugging, subagents, planning, memory,
  refactoring, dependencies, design-patterns.
- **Память — запись только после явного «да» автора.** Заметка о planka в памяти, записанная
  30.09 без спроса, оставлена с подтверждением автора.
- **Коммиты — только по явной просьбе, иначе предложить сообщение.**
- **Ponytail выключается автором:** его ядро — та же лестница объёма.
- **Строка приоритета в ядре:** просьба автора → `CLAUDE.md` проекта → «Решения» → остальные
  разделы ядра → модули.

## 3. Текст правил

Единственный источник — файлы репозитория: `philosophy.md` (ядро) и `rules/*.md` (модули).
Текст утверждён автором дословно 2026-10-07 и в спеке не дублируется.

Ядро: «Приоритет», «Решения» (прежний текст плюс фраза о фиксе-совпадении в пункте 6),
«Границы» (новый: деструктивные действия, коммиты, ослабление проверок, чужие правки, упавший
git-шаг, память, «спроси до», инъекции и секреты), «Поведение» (прежний текст плюс перепроверка
на возражение, цитирование увиденного, вызывающие перед правкой функции, доказательство «готово»,
прямые утверждения), «Спецификации» (прежний текст плюс факты и выборы в пункте 2), «Планы»
(прежний текст), «Модули» (индекс: имя файла и когда читать; каталог подставляется меткой
`{RULES}`).

Модули — по одному файлу на область, каждый начинается с условия «читай, когда». Места, где
формулировка источника спорила с ядром, заменены и помечены в тексте ссылкой на пункт ядра:
в `planning.md` владение файлами у задач обязательно; в `refactoring.md` простота — скорость
понимания, действует «Решения» 5.

## 4. Привязки модулей к судьям

| Хук | Срабатывает | Рубрика |
| --- | --- | --- |
| `PreToolUse`: `AskUserQuestion` | всегда | ядро «Решения» |
| `PreToolUse`: `ExitPlanMode` | всегда | ядро «Решения» + «Планы» + `planning.md` + `subagents.md` |
| `PreToolUse`: `Bash` | команда добавляет пакет | детерминированный отказ без модели, см. §6 |
| `Stop`, фильтр «варианты» | список из 2+ пунктов и слово из ряда «вариант», «рекоменд», «подход», option, approach | ядро «Решения» |
| `Stop`, фильтр «готово» | слово из ряда «готово», «сделано», «исправлено», «починено», «проходят», «зелёные», done, fixed, passing, complete | `verification.md` |

Оба фильтра `Stop` могут совпасть; тогда один вызов судьи с объединённой рубрикой и объединёнными
вопросами. Судья «готово» отвечает: названа ли команда-доказательство и процитирован ли её
увиденный вывод; взята ли команда из CI-конфига или task runner; названо ли непроверенное; для
фикса бага — прогнан ли исходный сценарий; числа из вывода команды. Сообщение, не заявляющее о
выполненной работе («готов обсудить»), проходит.

Модули `debugging.md`, `memory.md`, `refactoring.md`, `design-patterns.md` не привязаны ни к
одному хуку: ни один хук не видит «второй провал подряд», запись в память, рефакторинг или выбор
паттерна. Они действуют только когда агент сам их открыл по индексу. Это **долг**, принятый
автором осознанно.

## 5. Напоминание

`remind.py` подмешивает ядро целиком, как прежде; метка `{RULES}` заменяется абсолютным путём к
каталогу `rules/` плагина, иначе агенту некуда идти за модулем. Замена делается в
`common.philosophy_text`, единственном месте чтения ядра.

## 6. Хук зависимостей

Матчер `PreToolUse` расширяется до `AskUserQuestion|ExitPlanMode|Bash`. Для `Bash`
`judge_tool.py` проверяет команду детерминированно, без модели и без лимита отказов:

- Команда режется на сегменты по `&&`, `||`, `;`, `|` и переводам строки; в сегменте отбрасываются
  ведущие присваивания окружения и `sudo`.
- Добавление пакета: `go get <п>`; `npm install|i|add <п>`, `pnpm add|install|i <п>`,
  `yarn add <п>`; `pip|pip3 install <п>`, `python -m pip install <п>`, `uv pip install <п>` —
  только без `-r`/`--requirement`; `uv add`, `poetry add`, `cargo add`, `gem install`,
  `bundle add`, `composer require` с позиционным аргументом. Позиционный — слово не с `-`, не
  `.`/`..` и не путь, начинающийся с `./` или `/`.
- `npm ci`, `npm install` без пакета, `pip install -r` не трогаются.
- Маркер `PLANKA_DEP_OK=1` в команде пропускает её: автор согласился, агент повторяет команду с
  префиксом.
- Отказ с причиной: новая зависимость — вопрос автору; назови пакет, зачем, что из stdlib и
  установленного не закрывает; прочитай `rules/dependencies.md`; после согласия повтори с
  маркером. Журнал: `verdict: deny-dep`, `content` — команда.

## 7. Состав

```text
philosophy.md                — ядро
rules/*.md                   — восемь модулей
planka/common.py             — + rules_dir, rule_texts, rubric, подстановка {RULES}
planka/depcheck.py           — разбор команды на добавление пакета
planka/prompts.py            — + вопросы судьи «готово», сборка промпта Stop
planka/judge_tool.py         — + Bash, рубрика плана с модулями
planka/judge_stop.py         — + фильтр «готово», объединённая рубрика
hooks/hooks.json             — матчер с Bash
tests/                       — тесты на каждое, подмена claude как прежде
README.md                    — модули, хук зависимостей, маркер, долг
```

## 8. Проверка

`make test` с подменённым `claude`; `make validate`. Живая проверка автором: `Stop` с «готово»
без доказательства блокируется; `npm install left-pad` отклоняется, с `PLANKA_DEP_OK=1`
проходит; выход из плана без строки владения файлами судится по `planning.md`.
