# planka — документация проекта и комментарии: модули, настройки языка, судья по снимку дерева

Дата: 2026-10-07. Дополняет `2026-10-07-planka-modules-design.md`; базовая спека
`2026-09-30-planka-design.md` действует в остальном.

## 1. Задача

Режим документации проекта-образца — корневой `CLAUDE.md` как карта, `context/` как единый источник,
локальный `CLAUDE.md`-роутер в каждом изолированном каталоге, каталог отложенного с индексом —
становится правилом plugin для всех проектов. В проекте без документации, включая пустой, она
разворачивается по предложению агента и одному «да» автора; после каждой правки кода хук не
выпускает агента из хода, пока документация и комментарии не сверены. Правила комментариев —
сухие, по факту, без истории — переносятся из проекта-образца; язык комментариев и язык документации
задаются настройками плагина.

## 2. Решения автора (2026-10-07)

- Инициализация в проекте без `CLAUDE.md`: хук обнаруживает, агент предлагает, автор подтверждает
  один раз. Молчаливая запись отвергнута: решение о чужом репозитории за автора.
- Поддержка после правок: судья на `Stop` с детерминированным триггером «за ход изменился код» по
  снимку дерева файлов (размер, mtime), снятому на реплике; один код для git и не-git; видит правки
  субагентов. Рекомендательный режим и чтение транскрипта отвергнуты.
- Объём общего правила: `CLAUDE.md`, `context/`, отложенное, комментарии; пользовательская
  документация — по правилам `CLAUDE.md` проекта.
- Каталог отложенного — `context/deferred/` везде, включая переименование в проекте-образце (21 md-файл и
  `Makefile`). Два имени для одной сущности отвергнуты как долг.
- Язык: две настройки плагина, `comment_lang` (`en`, `ru`, `en+ru`) и `doc_lang` (`en`, `ru`), обе
  обязательные, без умолчания: язык каждого проекта выбран явно, скрытых соглашений нет. Единая
  настройка с зашитой парой «`en+ru` → документация по-русски» отвергнута.
- Судья комментариев видит сами комментарии из изменённых файлов, а не самоотчёт.
- «Границы» получают оговорку: ведение документации проекта по `rules/docs.md` — часть каждой
  правки, не нарушение запрета править `CLAUDE.md`.
- Пользовательских переменных окружения нет: модель судьи — настройка `judge_model` (умолчание
  `sonnet`); выключение — `claude plugin disable`, собственный выключатель `PLANKA_OFF` снят как
  второй источник состояния «включён». `PLANKA_JUDGE` остаётся служебной меткой вложенного вызова.
- Публикация: `.claude-plugin/marketplace.json` (маркетплейс `planka`, плагин `planka`,
  `source: ./`) для установки из `github.com/Comprise/planka`.

## 3. Тексты

Единственный источник — файлы репозитория. Новые: `rules/docs.md`, `rules/comments.md`. Правки
ядра `philosophy.md`: в «Границы» после пункта о генерируемом — оговорка; в «Модули» две строки
индекса и строка с языками. Тексты утверждены автором в диалоге и в спеке не дублируются.

Место подстановки: `{RULES}` как прежде; `{COMMENT_LANG}` и `{DOC_LANG}` заменяются значением
настройки в ядре и в тексте модулей, когда их читает судья (`common.rule_texts`). Агент, открывший
модуль с диска, видит метку; значения ему даёт строка индекса ядра. Незаданная настройка
подставляется как «не задан» и даёт строку `planka: задайте comment_lang и doc_lang: claude plugin
configure planka@<маркетплейс> --values-stdin; id — в claude plugin list` в stderr один раз на
сессию: короткий id без маркетплейса команда `claude plugin configure` не принимает.

## 4. Настройки

`.claude-plugin/plugin.json`, `userConfig`:

```json
{
  "judge_model": {"type": "string", "title": "Модель судьи", "default": "sonnet"},
  "comment_lang": {"type": "string", "title": "Язык комментариев", "options": ["en", "ru", "en+ru"], "required": true},
  "doc_lang": {"type": "string", "title": "Язык документации", "options": ["en", "ru"], "required": true}
}
```

Хуки читают `CLAUDE_PLUGIN_OPTION_JUDGE_MODEL`, `CLAUDE_PLUGIN_OPTION_COMMENT_LANG` и
`CLAUDE_PLUGIN_OPTION_DOC_LANG`. Проектный
`CLAUDE.md` конкретнее настройки и побеждает: модуль комментариев говорит это прямо. Поле с
`options` требует Claude Code ≥ 2.1.271; у автора 2.1.292.

## 5. Снимок дерева

`remind.py` на каждой реплике:

- Корень проекта — вершина git-репозитория для `cwd`, иначе `cwd`.
- Обход с исключением каталогов `.git`, `node_modules`, `__pycache__`, `.venv`, `venv`, `target`,
  `build`, `dist`, `.dart_tool`, `.superpowers`, `.audit`, `.data`, `.idea`, `.vscode` и записей
  корневого `.gitignore` без подстановочных знаков (имена каталогов и файлов) и вида `*.ext`.
- Запись `state/<session>.snap.json`: `prompt_id`, корень, `{относительный путь: [size, mtime_ns]}`.
- Больше 50 000 файлов — снимок не делается, строка `planka: дерево больше 50000 файлов, сверка
  документации не проверяется`; это долг, записанный в README.
- Если в корне нет `CLAUDE.md`, к контексту добавляется строка: «Проект без документации: предложи
  автору инициализацию по `rules/docs.md`».

## 6. Фильтр «документация» на `Stop`

`judge_stop.py` читает снимок текущего `prompt_id`, обходит дерево заново и считает изменённые
пути: добавленные, удалённые, изменившие размер или mtime. Файлы документации — `*.md`, `CLAUDE.md`,
`context/**`, `docs/**`, `README*`, `LICENSE*` — отделяются от файлов кода. Фильтр срабатывает,
когда изменён хотя бы один файл кода.

Содержимое для судьи: сообщение агента; список изменённых файлов с пометкой «код» или
«документация»; извлечённые комментарии из изменённых файлов кода. Извлечение: в git-репозитории —
добавленные строки `git diff --no-color -U0 HEAD -- <файлы>` плюс все строки неотслеживаемых
изменённых файлов; иначе — все строки изменённых файлов; из них остаются строки комментариев по
синтаксису расширения (`//`, `/* … */` для C-семейства, Go, Dart, Kotlin, Swift, JS/TS, Rust;
`#` для Python, shell, TOML, YAML, Makefile; `--` для SQL и Lua; `"""`/`'''` docstring Python;
`<!-- -->` для HTML/XML/Markdown-в-коде). Объём ограничен 300 строками и 16 КБ, обрезка помечается.

Рубрика: модули `rules/docs.md` и `rules/comments.md` целиком, с подставленными языками; строка
«В корне проекта нет CLAUDE.md.» в содержимом включает вопрос об инициализации. Вопросы судье: для каждого каталога с
изменённым кодом — назван ли его локальный `CLAUDE.md` и сверен ли; названы ли документы `context/`
по изменённому механизму; обновлены они или сказано, почему ничего не устарело; остаток записан в
`context/deferred/` или сказано, что остатка нет; комментарии — на заданном языке (или по правилу
проектного `CLAUDE.md`), без истории, без пересказа очевидного, факт, а не обоснование; если в корне
нет `CLAUDE.md` — предложена ли инициализация. Отказ формулируется как указание: какой файл сверить
или какую строку комментария переписать.

Три фильтра `Stop` — «варианты», «готово», «документация» — объединяются в один вызов, как прежде
два; лимит отказов общий для хука.

## 7. Состав правки

```text
philosophy.md                — оговорка в «Границах», индекс модулей, строка языков
rules/docs.md                — новый
rules/comments.md            — новый
.claude-plugin/plugin.json   — userConfig
.claude-plugin/marketplace.json — манифест маркетплейса
planka/common.py             — настройки, подстановка меток, корень проекта, классификация файлов
planka/snapshot.py           — обход, исключения, запись и сравнение снимка
planka/comments.py           — извлечение строк комментариев
planka/prompts.py            — вопросы «документация», stop_prompt с третьим флагом
planka/remind.py             — снимок, строка про отсутствие CLAUDE.md, предупреждение о языке
planka/judge_stop.py         — фильтр «документация», содержимое с файлами и комментариями
tests/                       — на каждое
README.md                    — настройки, модули, снимок, долг
```

Проект-образец: `git mv context/debt context/deferred`, замена ссылок в
21 md-файле и двух строках комментария `Makefile`, проверка ссылок. Отдельный коммит в своём
репозитории по регламенту проекта-образца.

## 8. Долг, принятый автором

- Порог 50 000 файлов для снимка.
- Извлечение комментариев знает перечисленные синтаксисы; язык с иным синтаксисом судится по
  самоотчёту.
- Судья видит только последнее сообщение агента: сверка обязана быть в нём названа.
- Пользовательская документация в новом проекте появляется только после записи правил в его
  `CLAUDE.md`.

## 9. Проверка

`make test` с подменённым `claude`; `make validate` (манифест с `userConfig`). Живая проверка
автором: правка кода без сверки блокируется с указанием файла; `claude plugin configure planka`
показывает обе настройки; в пустом каталоге с `git init` первая реплика несёт строку про
инициализацию.
