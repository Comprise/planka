# План: разбор bash по грамматике (shparse)

## Итог

Самописный лексер `depcheck.py` (`_scan`, `_parse`, `_close_paren`, `_quoted_substitutions`, `_funsub_step`,
`_heredoc_end`, `_body_line`, …) заменяется модулем `plugin/planka/shparse.py`, который читает текст так, как bash
5.3 (parse.y: read_token, parse_comsub, parse_matched_pair, shell_eof_token, make_here_document,
read_secondary_line, reserved_word_acceptable, parse_compound_assignment), и отдаёт одно дерево: команды, слова,
подстановки с телом и знаком конца, heredoc, комментарии. Над деревом работают три потребителя: `depcheck.py`
(вопросы `dependency_add`, `dependency_doubt`, `heredocs`, `_segments`, `_command`), `debug_watch.py` (сегменты
команды, пары скобок) и `comments.py` (heredoc и комментарии файлов sh/bash). Семантика менеджеров пакетов
(списки слов → добавление) переносится без изменений в `plugin/planka/pkgmanagers.py`. Новый разбор строится рядом
со старым, сравнивается со старым и с настоящим bash на корпусах и фаззере, затем старый удаляется.

Решения автора (ответы 2026-10-09): три модуля `shparse.py`, `pkgmanagers.py`, `depcheck.py`; корпус
транскриптов — в репозитории, обезличенный; `debug_watch` и `comments` тоже переходят на `shparse`; переход —
рядом и сравнить.

## Факты разведки

- Инструмент Bash Claude Code исполняет `/bin/bash -c 'source <снимок> … && shopt -u extglob … && eval '<команда>''`
  (`ps -o args= -p $$`, `$BASH_EXECUTION_STRING` в этой сессии). В снимке `shopt -u expand_aliases`, алиасов нет
  (`~/.claude/shell-snapshots/snapshot-bash-*.sh`). Значит: алиасы не раскрываются, `extglob` выключен.
- При синтаксической ошибке `eval` в этой обёртке и `bash -c` ведут себя одинаково на проверенных формах: команды до
  ошибки исполняются, после неё — нет; ошибка скобок присваивания массива отбрасывает свою строку (с телами её
  heredoc), следующие строки исполняются (прогон `touch` в пустом каталоге, scratchpad `evalprobe`).
- bash в системе — 5.3.20; `bwrap` 0.13.0 и `unshare -rn` доступны.
- Внешние пользователи `depcheck`: `judge_tool` (`dependency_add`, `dependency_doubt`, `DEP_OK_MARKER`),
  `manifest_watch` (`dependency_add`, `DEP_OK_MARKER`, `_segments`, `_command`, `_split`, `_subcommand`,
  `_takes_value`, `_basename`, `_NO_VALUE_FLAGS`, `_REDIRECT`), `comments` (`heredocs`); тесты обращаются ещё к
  `_quoted_substitutions` (15 раз), `_split` (8), `_takes_value`, `_WHY_*`, пределам `_MAX_*`, `_WORDS_LIMIT`, наборам
  флагов.
- Транскрипты: 245 файлов `~/.claude/projects/**/*.jsonl`, 9509 уникальных команд `Bash` (`tool_use` с
  `input.command`). Временный корпус 8073 команд —
  `/tmp/claude-1000/-home-elia-Projects-planka/2526528d-29db-43ca-b9a1-97e1c6e08856/scratchpad/review/r2-code/corpus.jsonl`;
  план на него не опирается: корпус пересобирается задачей 1.
- unittest находит только `tests/test*.py` и пакеты с `__init__.py`; каталог `tests/tools/` без `__init__.py` в
  прогон не попадает.

## Ошибка дешевле

Ложный отказ дешевле пропуска: пропуск — незамеченная установка пакета, отказ снимается маркером
`PLANKA_DEP_OK=1` (как сейчас, `CLAUDE.md`: «Сомнение детектора зависимостей — отказ с обходом маркером»). Отсюда:
после фатальной синтаксической ошибки, которую видит `shparse`, детектор продолжает проверять остаток текста
(восстановление со следующей строки, как сейчас); `debug_watch` и `comments` следуют bash точно.

## Контракт `shparse` (фиксирует задача 4, опираются задачи 5–10)

Модуль без состояния, только stdlib, без рекурсии Python по глубине входа (явный стек): разбор и обход линейны по
длине текста.

- `parse(text, eof="") -> Script`. `eof` — знак конца heredoc внешней подстановки (`")"`, `"}"`, `""`), с которым
  разбирается тело подстановки отдельно (как `_Body` сейчас).
- `Script`: `commands` — полные команды в порядке чтения bash (до перевода строки верхнего уровня, вместе с телами
  heredoc); `error` — `None` или `SyntaxIssue(pos, fatal)`: `fatal=True` — bash прекращает чтение;
  `fatal=False` — ошибка скобок массива, строка отброшена, чтение продолжено (`dropped` — диапазоны отброшенного
  текста); `comments` — список `(start, end)`.
- Узлы (класс на вид, поля — позиции `start`, `end` в `text` и дети): `Simple(assigns, words, redirs)`,
  `Pipeline(commands, bang, time)`, `AndOr(items, ops)`, `Sequence(items, seps)` (`;`, `&`, перевод строки),
  `Subshell`, `Group`, `If`, `While`, `Until`, `For`, `Select`, `Case`, `Function(name, body)`, `Coproc`,
  `ArithCmd(expr)`, `Cond(words)` (`[[ … ]]`).
- `Word(parts)`; части: `Lit(text)`, `SQ(text)`, `DQ(parts)`, `AnsiC(value)`, `Param(text, parts)` (`${…}` с частями
  операторов, `$x`, `$$`), `Sub(kind, body: Script, start, end)` (`kind` ∈ `"$("`, `` "`" ``, `"${ "`, `"${|"`,
  `"<("`, `">("`), `Arith(parts)` (`$((…))`, `$[…]`, индексы и смещения, которые bash раскрывает арифметикой;
  подстановки в её `'…'` — `Sub`). `Word.literal()` — значение после снятия кавычек или `None`, если в слове есть
  раскрытие.
- `Redir(op, fd, target: Word | Heredoc)`; `Heredoc(term, strip_tabs, quoted, body_start, body_end, parts)`:
  `parts` — части тела без кавычек у терминатора (подстановки в нём — `Sub`), у терминатора в кавычках — один `Lit`.
- `walk(node)` — все узлы, итеративно; `simple_commands(script)` — все `Simple`, в том числе в телах `Sub`, функций,
  `Arith`-подстановок, в порядке текста; после фатальной ошибки — не дальше неё.
- Совместимость: `heredocs(line)` (порядок и форма — как `depcheck.heredocs` сейчас; `depcheck.heredocs` становится
  его вызовом).

## Безопасность — обязательна для каждой задачи

- Команды из корпусов и транскриптов не исполняются никогда — ни в bash, ни в другой оболочке. Корпус только
  читается и разбирается Python.
- В bash исполняются только формы генератора фаззера, где единственное внешнее действие — `touch PWNED`;
  менеджеры пакетов не запускаются никогда, в том числе «для проверки».
- Исполнение — только через `tests/tools/bashdiff.py`, только внутри `bwrap` (корень только для чтения, запись — в
  каталог случая, сеть выключена, `--die-with-parent`, `--clearenv`); без `bwrap` фаззер не стартует.
- Файлы случаев пишутся инструментом Write или из Python, не heredoc в оболочке.
- Удаление файлов вне своего scratchpad — только с согласия автора через координатора.
- Только тесты затронутого функционала — изменённых модулей и тех, кто их вызывает; полный `make test`/`make check` — только
  по просьбе автора; запуск Python, разбирающего формы, — под `prlimit --as=2000000000`, фаззер — не больше `--jobs 4`; зелёность дерева объявляет
  координатор.

### Задача 2: дифференциальный фаззер против bash

**Файлы:** `tests/tools/bashdiff.py`, `Makefile`

Ярус: фронтир (безопасность).

- Генератор форм из фрагментов грамматики: кавычки всех видов, `\`, подстановки `$(`, `` ` ``, `${ `, `${|`, `<(`,
  `>(`, `$((`, `$[`, `${…}` с операторами, heredoc (`<<`, `<<-`, кавычки терминатора, склейка `\`, несколько на
  строке, внутри подстановок разного вида), комментарии, скобки массива, `case`, `[[ ]]`, `if`/`while`/`for`,
  подоболочки, группы, конвейеры, синтаксические ошибки. Маркеры — `touch P<n>`; генератор ставит их только туда,
  где команда исполнится, если bash прочтёт её командой (без `false &&`, без невызванных функций). Входы — только
  генератор с зерном; чтения команд из файлов и stdin нет.
- Исполнение: обёртка Claude Code (`bash -c 'shopt -u extglob 2>/dev/null || true && eval '<форма>''`) внутри `bwrap
  --ro-bind / / --dev /dev --proc /proc --tmpfs /tmp --bind <каталог случая> <каталог случая> --chdir <каталог
  случая> --unshare-all --die-with-parent --clearenv --setenv PATH /usr/bin:/bin`, таймаут 5 с. Исполненные
  маркеры — созданные файлы `P<n>`.
- Режимы: `--target detector --engine old|new` — маркер с подставленным для детектора `npm i evil` исполнен, а
  детектор молчит → потеря; не исполнен, а детектор отказал → строгость (счётчик). `old` — публичные
  `dependency_add`/`dependency_doubt`, `new` — `depcheck._tree_add`/`_tree_doubt` (имена из контракта задачи 5).
  `--target parser` — множество исполненных маркеров сравнивается с именами `touch P<n>` в
  `shparse.simple_commands`; импорт `shparse` — внутри режима (модуль появится в волне 1). `--compare old new` —
  расхождения движков на одних формах.
- Вывод — JSON строк расхождений в каталог из аргумента `--out`; код выхода 1 при потере.
- `Makefile`: цель `bashdiff` — фиксированное зерно и число форм по умолчанию (не меньше 20000 форм за прогон).
  В `check` не входит.
- Проверка пакета: прогон `--target detector --engine old` на 2000 форм; отчёт о найденных потерях — это данные, не
  задача их чинить.
- Сообщить координатору: скорость (форм в секунду), найденные потери старого движка поимённо.

## Допущения

- Claude Code исполняет команды через обёртку `bash -c … eval` (проверено на этой машине, Linux); на других
  платформах и в будущих версиях обёртка может отличаться.
- Пользователь запускает bash 5.x; у пользователей с zsh (macOS по умолчанию) детектор читает команду грамматикой
  bash — строка в README.
- sh-файлы в `comments` читаются грамматикой bash (bash — надмножество POSIX sh в части комментариев и heredoc).
- Модуль `shparse` без состояния — конкурентный доступ не проверяется.
- Секреты в корпусе ищутся по перечисленным шаблонам; остальное ловит просмотр автора.

## Отвергнутые варианты

- Продолжать чинить формы по одной: восемь волн, каждое ревью находило новые формы — лечит симптом.
- Спрашивать bash (`bash -n`, `set -n`): нужен bash 5.3 у пользователя (на macOS — 3.2), дерево bash не отдаёт.
- `shlex`, сторонние разборщики (bashlex, tree-sitter-bash): не грамматика bash 5.3 или не stdlib.
- Генерировать разбор из parse.y: грамматика yacc без read_token — а он и есть трудная часть.
- Фаззер без песочницы или с прогоном корпуса: прошлая сессия дважды исполнила команды корпуса и стёрла файлы.

## Отложенный долг

- zsh: команды пользователей zsh детектор читает грамматикой bash (README).
- Встроенный shell в Make и YAML в `comments` остаётся на общем движке.
