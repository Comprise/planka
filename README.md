# planka

Плагин Claude Code уровня пользователя: на каждую реплику подмешивает `philosophy.md` в
контекст, а в точках выбора — вопрос автору, выход из плана, сообщение со списком вариантов —
судья-модель отклоняет рекомендацию лёгкого пути вместо правильного.

## Установка

Плагин ставится только из маркетплейса (манифест `.claude-plugin/marketplace.json`). Id плагина —
`planka@planka`.

Удалённый маркетплейс, репозиторий `github.com/Comprise/planka`:

```bash
claude plugin marketplace add Comprise/planka
claude plugin install planka@planka
```

Для разработки — маркетплейс из рабочей копии (путь клона, например `~/Projects/planka`):

```bash
claude plugin marketplace add ~/Projects/planka
claude plugin install planka@planka
```

Правки файлов подхватываются в следующей сессии или по `/reload-plugins`.

Обязательная настройка языков: пока `comment_lang` и `doc_lang` не заданы, хук `UserPromptSubmit`
раз за сессию показывает предупреждение `planka: задайте comment_lang и doc_lang: claude plugin
configure planka@planka --values-stdin`.

```bash
claude plugin configure planka@planka --values-stdin <<< '{"comment_lang":"en+ru","doc_lang":"ru"}'
```

Переход со старой установки ссылкой: если `claude plugin list` показывает `planka@skills-dir`,
перед добавлением маркетплейса выполнить `rm ~/.claude/skills/planka`: иначе один плагин установлен дважды, под двумя id.

Требования: `python3` 3.10+, `claude` в `PATH`, вход в Claude Code выполнен (OAuth или ключ).

## Настройки

Задаются через `claude plugin configure <id>`; текущие значения — `claude plugin configure <id> --json`.
Список и умолчания — `userConfig` в `.claude-plugin/plugin.json`.

| Настройка | Значения | Действие |
| --- | --- | --- |
| `judge_model` | любая модель `claude`; по умолчанию `sonnet` | модель вложенного судьи |
| `comment_lang` | `en`, `ru`, `en+ru` | язык комментариев в коде; `en+ru` — английский, затем русский перевод; обязательна |
| `doc_lang` | `en`, `ru` | язык `CLAUDE.md`, `context/`, `deferred/`; обязательна |

Выключение плагина — `claude plugin disable <id>`. Переменных окружения для пользователя нет:
`PLANKA_JUDGE` — служебная метка вложенного вызова судьи (см. «Как это работает»).

Предупреждения и внутренние ошибки хуков доходят до пользователя полем `systemMessage` JSON-ответа
хука; stderr хуки не пишут.

## Как это работает

Правила — это ядро `philosophy.md` и модули `rules/*.md` (по файлу на область, каждый начинается
с условия «читай, когда»), среди них `docs.md` (документация проекта) и `comments.md` (комментарии
в коде).

- `UserPromptSubmit` → `planka/remind.py`: весь `philosophy.md` как `additionalContext`. В конце
  ядра — индекс «Модули»; метка `{RULES}` в нём на каждой реплике заменяется абсолютным путём к
  каталогу `rules/` плагина, чтобы агент знал, где открыть модуль; метки `{COMMENT_LANG}` и
  `{DOC_LANG}` подставляются значениями настроек в строку «Язык комментариев: …; язык
  документации: …» индекса и в модули.
  Тот же хук снимает снимок дерева проекта: корень — вершина git для `CLAUDE_PROJECT_DIR`
  (каталог запуска сессии; после `cd` агента он не меняется), без неё — для `cwd`; вне git — сам
  каталог; для каждого файла хранятся размер и mtime; пропускаются каталоги из
  `snapshot.IGNORED_DIRS`
  (`.git`, `node_modules`, `__pycache__`, `.venv`, `venv`, `target`, `build`, `dist`,
  `.dart_tool`, `.superpowers`, `.audit`, `.data`, `.idea`, `.vscode`) и записи корневого
  `.gitignore` без подстановочных знаков и вида `*.ext`. Снимок пишется в `state/<session>.snap.json`.
  Если в корне нет `CLAUDE.md`, к контексту добавляется строка «Проект без документации: предложи
  автору инициализацию по rules/docs.md.»
- `PreToolUse` на `AskUserQuestion|ExitPlanMode|Bash` → `planka/judge_tool.py`: вопрос — по
  разделу «Решения»; план — сначала детерминированная проверка владения файлами в волне, потом
  судья по «Решениям», «Планам» и модулям `planning.md` и `subagents.md`. Текст плана берётся из
  файла, путь которого записан в транскрипте.
- `Stop` → `planka/judge_stop.py`: два текстовых фильтра по последнему сообщению агента и фильтр
  «документация» по изменениям дерева с момента снимка. Совпавшие фильтры — один вызов судьи и
  общий лимит отказов.

Рубрики судьи:

| Хук | Срабатывает | Рубрика |
| --- | --- | --- |
| `AskUserQuestion` | всегда | «Решения» |
| `ExitPlanMode` | всегда | «Решения» + «Планы» + `planning.md` + `subagents.md` |
| `Stop`, фильтр «варианты» | в сообщении 2+ пункта списка и слово «рекоменд», «вариант», «подход», `recommended`, `option` или `approach` | «Решения» |
| `Stop`, фильтр «готово» | в сообщении слово из списка ниже | `verification.md` |
| `Stop`, фильтр «документация» | со снимка текущей реплики изменился хотя бы один файл кода | `docs.md` + `comments.md` |

Слова фильтра «готово» (регистр не важен, целое слово): «готово/готова/готовы»,
«сделан/сделано/сделана/сделаны», «исправлен/исправлено/исправлена/исправлены»,
«починен/починено/починена/починены», «проходит», «проходят», «прошёл», «прошли», «зелёный» и
его формы, `done`, `fixed`, `passing`, `passes`, `complete`, `completed`. Если совпали оба
фильтра, судья вызывается один раз: рубрика и вопросы объединены. Судья «готово» проверяет, что
названа команда-доказательство и процитирован её увиденный вывод, что команда взята из CI-конфига,
манифеста или task runner, что названо непроверенное, что для фикса бага прогнан исходный
сценарий и что числа взяты из вывода. Сообщение без заявки о выполненной работе («готов
обсудить») проходит.

Фильтр «документация»: каждый изменённый файл относится к одному из трёх классов. Код — файл с
расширением из `CODE_EXTS` (`common.py`: go, c, cpp, java, kt, swift, js, mjs, ts, mts, dart, rs,
cs, py, pyi, sh, rb, toml, yaml, ini, cmake, sql, lua, html, xml и другие) или с именем из
`CODE_NAMES` (`Makefile`, `makefile`, `GNUmakefile`, `CMakeLists.txt`, `Dockerfile`, `Justfile`,
`Rakefile`, `Gemfile`), в любом каталоге. Документация — остальные `*.md`, `README*`, `LICENSE*` и
всё под `context/` и `docs/` от корня. Прочее — всё остальное. Фильтр
запускает изменённый, добавленный или удалённый файл кода; изменение файлов «прочее» и документации
его не запускает. Судья видит последнее сообщение агента, список изменённых файлов с
пометками «код», «документация» и «прочее» (удалённый файл — с пометкой «удалён»; список не длиннее
`MAX_LISTED` = 100, остаток — строкой «и ещё N»), строки комментариев из изменённых файлов кода и, если в корне
нет `CLAUDE.md`, строку об этом. Строки комментариев: для файла под git, отслеживаемого, — добавленные
строки `git diff -U0 HEAD`; для неотслеживаемого и вне git — файл целиком; синтаксисы — по
расширению: `//` и `/* */` (go, c, cpp, java, kt, swift, js, ts, dart, rs, cs и др.), `#` (py, sh,
rb, toml, yaml, mk, cmake, Makefile, CMakeLists.txt и др.; для py и pyi ещё docstring), `--` (sql, lua, hs), `<!-- -->` (html,
xml, vue, svelte). Предел — 300 строк и 16 КБ, при обрезке судье сообщается об этом. Рубрика —
`rules/docs.md` и `rules/comments.md` с подставленными языками.

Хук `PreToolUse` на `Bash` — детерминированный: без модели и без лимита отказов. Команда
режется на сегменты по `&&`, `||`, `;`, `|` и переводам строки вне кавычек: текст в кавычках,
в том числе многострочный, — данные; `\` в конце строки продолжает сегмент; ведущие присваивания окружения
и `sudo` отбрасываются. Тело heredoc (`<<EOF`, `<<'EOF'`, `<<-EOF`) до строки-терминатора не
разбирается: это данные, а не команды; строка с самим `<<` проверяется. Отклоняется добавление
пакета: `go get`; `npm install|i|add`, `pnpm add|install|i`, `yarn add`; `pip`/`pip3 install`,
`python -m pip install`, `uv pip install`, `uv add`; `poetry add`, `cargo add`, `bundle add`,
`gem install`, `composer require` — если есть позиционный аргумент. Не считаются добавлением:
`pip install -r` и `--requirement`, `npm ci`, установка по lockfile без пакета (`npm install`,
`pnpm install`), значения флагов (`--prefix`, `-c` и подобные), локальные пути (`.`, `./x`,
`/x`, `~`, `file:`), архивы `*.whl` и `*.tar.gz`, установка через pip только `pip`,
`setuptools` и `wheel` (например, `pip install --upgrade pip`) и текст после `#` в комментарии.
Отказ говорит агенту: новая зависимость — вопрос автору; назови пакет, зачем он и что из
stdlib или установленного не закрывает; прочитай `rules/dependencies.md`. Когда автор
согласился, агент повторяет команду с маркером `PLANKA_DEP_OK=1`: это текстовый маркер внутри
самой команды (например, `PLANKA_DEP_OK=1 npm install left-pad`), а не переменная окружения,
которую нужно выставлять глобально. Отказы пишутся в журнал с `verdict: deny-dep`.

Судья — вложенный `claude -p` с `--setting-sources ""`, поэтому хуки плагинов в нём не
загружаются; вторая защита — `PLANKA_JUDGE=1`. Инструменты у судьи отключены (`--tools ""`): он
только читает промпт и отвечает JSON по схеме. Отказ приходит агенту как ошибка инструмента
или как причина продолжить работу; причина начинается с `planka: `. Не больше двух отказов на
одну реплику автора для одного хука — в лимит входят отказы судьи и детерминированный отказ
плана по владению файлами; третий вызов проходит с предупреждением `planka: лимит отказов, пропущено без проверки`.
На отказы хука зависимостей лимит не распространяется.

Журнал вердиктов: `judge.log` в `$CLAUDE_PLUGIN_DATA`, по строке JSON на
решение хука: вердикт судьи, его пропуск и лимит, а также решения без вызова судьи — `deny-dep`,
`deny-files`, `budget` отказа плана по файлам и `skipped`, когда нет плана или рубрики. Вызов хука
без проверки (команда Bash без добавления пакета, сообщение без совпавшего фильтра) в журнал не
пишется. Строка хранит только метаданные: хук, вердикт, причину, сработавшие фильтры, длительность,
`content_len` и `content_sha256` проверенного содержимого и `files` (изменённые файлы хука `Stop`,
не больше `MAX_LISTED`); само содержимое не пишется. Отказ по зависимости пишется без причины: она
цитирует команду. При размере от `LOG_MAX_BYTES` (1 МиБ) файл переименовывается в `judge.log.1`;
ротация и запись идут под блокировкой `judge.log.lock`. Ответ хука выдаётся и при сбое записи
журнала, вместе с предупреждением «внутренняя ошибка». Счётчики отказов — там же в `state/`; файл сессии, не менявшийся 7 дней, удаляется.

## Известные ограничения

- Модули `debugging`, `memory`, `refactoring`, `design-patterns` не привязаны ни к одному хуку:
  ни один хук не видит «второй провал подряд», запись в память, рефакторинг или выбор паттерна.
  Они действуют, только если агент сам открыл их по индексу. Это зафиксированный долг.
- Фильтр «готово» — словесная эвристика и даёт ложные срабатывания: «прошёл», «зелёный», `done`
  или `complete` в обычной прозе. Цена ложного срабатывания — лишний вызов судьи; судья такое
  сообщение пропускает, если оно не заявляет о выполненной работе.
- Детектор зависимостей знает только перечисленные менеджеры. Имя пакета в переменной
  (`npm install $PKG`) отклоняется, хотя пакет неизвестен. Не видит детектор подоболочку
  `$(...)`, абсолютный путь к бинарнику, `npm.cmd` и обёртки вроде `time`, `env`, `sh -c`. На
  слова разбираются первые 4096 символов сегмента: пакет, названный дальше, не виден.
- `judge.log` содержимого не хранит, но поле `reason` — текст судьи и может цитировать проверенное
  содержимое (строки комментариев, фрагменты плана). Секрет в командной строке или закомментированный
  ключ в `toml`/`yaml`/`ini` уходит к судье в промпте.
- Показ `systemMessage` для событий `UserPromptSubmit`, `PreToolUse` и `Stop` взят из общего раздела
  документации по хукам и вживую не проверен.
- Расширение кода вне `CODE_EXTS` считается «прочее» и проверку документации не запускает.
- Фильтр хука `Stop` — текстовая эвристика (два пункта списка и слово вроде «вариант»,
  «рекомендую», «option»); сообщение с вариантами в прозе он пропустит.
- Любая ошибка судьи (нет сети, таймаут, неразбираемый ответ) или самого хука — пропуск со
  предупреждением `planka: ...` в `systemMessage`, не блокировка.
- Детерминированная проверка файлов в плане работает только при строке `Файлы:`/`Files:` в
  каждой задаче и заголовках `Волна N`/`Задача N:`; без них план целиком проверяет модель.
  Задачи до первого заголовка волны в проверке владения не участвуют.
  Содержимое fenced-блоков кода не разбирается; задача с `Файлы: нет` в проверке
  владения не участвует.
- Фильтр «документация» не запускается, если дерево больше 50 000 файлов (`snapshot.DEFAULT_MAX_FILES`):
  снимок не делается, предупреждение один раз на сессию, сверка документации не проверяется
  (принятый долг).
- Строки комментариев извлекаются только для синтаксисов из `comments.py`; файлы остальных языков
  судятся по самоотчёту агента.
- Судья видит только последнее сообщение агента: сверка документации должна быть названа в нём.
- `.gitignore` читается упрощённо: учитываются имена без подстановочных знаков и записи вида
  `*.ext`; `/name` и `name/` трактуются как имя в любом каталоге.
- Правка только документации фильтр «документация» не запускает. Без `prompt_id` во входе хука
  фильтр не срабатывает.
- Субагенты не получают напоминания: у них нет реплик автора. Философия при проблеме едет
  внутри текста задачи в плане — судья плана проверяет, что она там есть.
