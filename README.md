# planka

Плагин Claude Code уровня пользователя. Он держит агента в правилах работы `plugin/philosophy.md` и
`plugin/rules/*.md`: подмешивает их в контекст на каждую реплику и отклоняет действия, которые их нарушают.

Что проверяется:

- **Выбор между вариантами.** Вопрос автору, выход из плана и сообщение с вариантами смотрит судья-модель: рекомендован
  ли самый правильный вариант, а не самый лёгкий.
- **План.** Файл не принадлежит двум задачам одной волны; у задач есть всё, чтобы отдать их субагентам.
- **Заявка «готово».** Названа команда-доказательство, показан её вывод, перечислено непроверенное.
- **Документация.** После правки кода сверены `CLAUDE.md`, `context/` и комментарии.
- **Модель субагента.** Ярус модели соответствует классу задачи.
- **Постоянная память.** Запись проходит только с явного согласия автора.
- **Новая зависимость.** Команда установки пакета или правка манифеста отклоняется без согласия автора.
- **Повторная неудача команды.** На второй неудаче подряд агент получает модуль отладки.

## Установка

Плагин ставится только из маркетплейса (манифест `.claude-plugin/marketplace.json`). Id плагина —
`planka@planka`.

Удалённый маркетплейс, репозиторий `github.com/Comprise/planka`:

```bash
claude plugin marketplace add Comprise/planka
claude plugin install planka@planka
```

Для разработки — маркетплейс из рабочей копии (путь клона, например `~/Projects/planka`):

```bash
claude plugin marketplace add ~/Projects/planka
claude plugin install planka@planka
```

Установленный плагин — копия в `~/.claude/plugins/cache/planka/planka/<version>/`: правки рабочей
копии в неё сами не попадают. Обновление — `claude plugin marketplace update planka`, затем
`claude plugin update planka@planka` и перезапуск сессии; подхватит ли обновление правки при той же
`version` в `plugin/.claude-plugin/plugin.json`, не проверено.

Языки по умолчанию — `ru`; другие задаются так:

```bash
claude plugin configure planka@planka --values-stdin <<< '{"comment_lang":"en+ru","doc_lang":"ru"}'
```

Переход со старой установки ссылкой: если `claude plugin list` показывает `planka@skills-dir`,
перед добавлением маркетплейса выполнить `rm ~/.claude/skills/planka`: иначе один плагин установлен дважды,
под двумя id.

Требования: POSIX — Linux, macOS, WSL (без `fcntl` каждый хук отвечает только предупреждением и ничего не
проверяет), `python3` 3.11+ (разбор TOML — `tomllib`), `claude` в `PATH`, вход в Claude Code выполнен (OAuth или ключ).

## Настройки

Задаются через `claude plugin configure <id>`; текущие значения — `claude plugin configure <id> --json`.
Список и умолчания — `userConfig` в `plugin/.claude-plugin/plugin.json`.

| Настройка | Значения | Действие |
| --- | --- | --- |
| `judge_model` | `session`, `sonnet`, `opus`, `haiku`, `fable`; по умолчанию `session` | модель вложенного судьи; `session` — модель текущей сессии |
| `comment_lang` | `en`, `ru`, `en+ru`; по умолчанию `ru` | язык комментариев в коде; `en+ru` — английский, затем русский перевод |
| `doc_lang` | `en`, `ru`; по умолчанию `ru` | язык `CLAUDE.md`, `context/`, `deferred/` |

Выключение плагина — `claude plugin disable <id>`. Переменных окружения для пользователя нет:
`PLANKA_JUDGE` — служебная метка вложенного вызова судьи.

Предупреждения и внутренние ошибки хуков доходят до пользователя полем `systemMessage` JSON-ответа
хука; stderr хуки не пишут.

## Что видит пользователь

- Отказ приходит агенту, а не вам: агент получает причину и исправляет действие сам. Причина начинается с
  `planka: Мой дорогой друг, `.
- Не больше двух отказов одного хука на одну вашу реплику. Дальше проверка пропускается с предупреждением
  `planka: лимит отказов, пропущено без проверки`, чтобы агент не застрял в цикле.
- Ошибка судьи или хука никогда не блокирует работу: проверка пропускается, а вы видите предупреждение.
- Судья — вложенный `claude -p` на модели из настройки `judge_model`. Каждый вызов тратит запрос к модели.
- Журнал решений — `judge.log` в каталоге данных плагина (`$CLAUDE_PLUGIN_DATA`). В нём только метаданные: вердикт,
  хук, длительность, длина и SHA-256 проверенного содержимого. Поле `reason` — текст судьи, он может цитировать
  проверенное.

### Если отказ по зависимости ложный

Детектор зависимостей работает без модели и по сомнению отказывает. Если вы согласны на установку или отказ
ложный, попросите агента поставить перед командой маркер `PLANKA_DEP_OK=1`:

```bash
PLANKA_DEP_OK=1 npm install lodash
```

Тот же маркер снимает блок после команды, которая дописала новый пакет в манифест.

## Известные ограничения

- Судья в конце хода включается, только когда последнее сообщение агента просит вашего решения: в нём есть варианты
  или знак «?» в последнем абзаце. Заявка «готово» в сообщении без вопроса не проверяется.
- Фильтры «варианты» и «готово» — словесные эвристики. Они пропускают варианты, описанные прозой, и иногда зовут судью
  зря. Лишний вызов судьи ничего не блокирует.
- Детектор зависимостей знает только перечисленные в коде менеджеры пакетов, обёртки и оболочки. Он не видит команду
  установки, собранную во время исполнения: из переменных окружения, в цикле, в коде программы.
- Строка с командой установки внутри аргументов другой программы (`git grep 'npm install x'`, `python3 -c "…"`)
  может дать ложный отказ. Обход — маркер `PLANKA_DEP_OK=1`.
- Команды читаются по грамматике bash 5.3. На macOS инструмент Bash исполняет их в zsh, и форма, которую zsh читает
  иначе, может пройти мимо детектора.
- Без `fcntl` (не POSIX-система) хуки ничего не проверяют и только предупреждают.

Каждый известный край эвристик закреплён тестом в `tests/`. Устройство плагина описано в `context/architecture.md`.
