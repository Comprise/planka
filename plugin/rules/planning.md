# План или спека как результат

Читай, когда результат — план, спека или запись решения вместо правки.

- План закончен, когда он decision-complete: исполнитель — человек, агент, ты
  завтра — не принимает ни одного решения. Открытый выбор будет сделан дважды
  и по-разному.
- Планирование — только чтение: поиск, чтение, сухие прогоны, сборки и тесты,
  трогающие только кеши. Правка файлов, форматер, codegen, миграция — уже
  исполнение; переход к нему решает следующая реплика автора, не твоя
  трактовка.
- Разведай до вопроса: хотя бы один проход по репозиторию — точки входа,
  конфиг, схемы, вызовы. Факт — где живёт символ, какая версия закреплена,
  как ведёт себя код — ищется и не спрашивается; спрашивается то, где после
  поиска осталось несколько кандидатов, с рекомендацией.
- Предпочтение или компромисс — объём, приоритет, один из двух годных
  дизайнов — спрашивай рано, до того как план застынет вокруг догадки. Вопрос
  меняет план, фиксирует допущение или выбирает между реальными компромиссами;
  2–4 взаимоисключающих варианта по «Решениям» 4.
- Заданный, но не отвеченный вопрос разрешается в рекомендуемое и
  записывается допущением.
- Форма: заголовок и короткие разделы — итог, изменения по поведению,
  проверка, допущения, отвергнутые варианты, отложенный долг; раздел границ —
  где границу легко пересечь по ошибке. В плане для субагентов у каждой задачи
  обязательна строка владения файлами (раздел «Планы» 1–2); по поведению
  описывается содержимое задачи, не её владение.
- Формат плана для субагентов: волна — заголовок `## Волна N`, задача —
  `### Задача N: <заголовок>`, владение — строка `**Файлы:**` с путями в
  обратных кавычках через запятую (`**Файлы:** нет` — задача без файлов). По
  этому формату пересечение владения в волне проверяется без модели.
- Спека или план, который трогает разбор входа, хук, сервис или CLI, до кода
  перечисляет классы входов и окружений и каждому даёт тест или запись
  допущения. Разбор: кавычки и экранирование, пустой и огромный вход,
  не-UTF-8, конкурентный доступ. Хук, сервис, CLI: локаль, чужой конфиг
  инструментов (git и т. п.), битое и чужое состояние, нет сети или бинаря,
  таймаут.
- План, который добавляет или меняет эвристику, детектор или разборщик
  входа, называет дешёвую ошибку — ложное срабатывание или пропуск — и
  корпус настоящих входов по `{RULES}/heuristics.md`.
- Новое правило проекта — в `CLAUDE.md`, `context/`, конфиге — получает
  проверку: тест, хук, вопрос судье, линт; правило без неё помечается
  непроверяемым.
- Планируй то, что просили: выдуманная схема, политика валидации, формат
  провода — решения, которых никто не принимал; не включай, пока их
  отсутствие не ведёт к конкретной ошибке.
- Не повторяй известное исполнителю: факты репозитория и инварианты из его
  `CLAUDE.md`. Что трогать нельзя в этой задаче, называется (ядро, «Планы» 1).
- План кончается планом, без «продолжать?». Пересмотренный план заменяет
  предыдущий целиком, не дельтой. Нет плана для одного очевидного шага.
- Принятую запись решения не правят под новое решение: пишут новую, старую
  помечают заменённой.
