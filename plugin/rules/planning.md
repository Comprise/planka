# План или спека как результат

Читай, когда результат — план, спека или запись решения, а не правка.

- План закончен, когда он decision-complete: исполнитель — человек, агент, ты
  завтра — не принимает ни одного решения. Открытый выбор будет сделан дважды
  и по-разному.
- Планирование — только чтение: поиск, чтение, сухие прогоны, сборки и тесты,
  трогающие только кеши. Правка файлов, форматер, codegen, миграция — уже
  исполнение; переход к нему решает следующая реплика автора, не твоя
  трактовка.
- Разведай до вопроса: хотя бы один проход по репозиторию — точки входа,
  конфиг, схемы, вызовы. Факты ищутся (раздел «Спецификации» 2); спрашивается
  то, где после поиска осталось несколько кандидатов, с рекомендацией.
- Предпочтение или компромисс — объём, приоритет, один из двух годных
  дизайнов — спрашивай рано, до того как план застынет вокруг догадки. Вопрос
  меняет план, фиксирует допущение или выбирает между реальными компромиссами;
  2–4 взаимоисключающих варианта по «Решениям» 4.
- Неотвеченный необязательный вопрос разрешается в рекомендуемое и
  записывается как допущение.
- Форма: заголовок и три–пять коротких разделов — итог, изменения по
  поведению, проверка, допущения; раздел границ — где границу легко пересечь
  по ошибке. В плане для субагентов у каждой задачи обязательна строка владения
  файлами (раздел «Планы» 1–2); по поведению описывается содержимое задачи, не
  её владение.
- Планируй то, что просили: выдуманная схема, политика валидации, формат
  провода — решения, которых никто не принимал; не включай, пока их
  отсутствие не ведёт к конкретной ошибке.
- Не повторяй известное исполнителю: факты репозитория, инварианты в каждом
  пункте, перечни неизменяемого.
- План кончается планом, без «продолжать?». Пересмотренный план заменяет
  предыдущий целиком, не дельтой. Нет плана для одного очевидного шага.
- Принятую запись решения не правят под новое решение: пишут новую, старую
  помечают заменённой.
